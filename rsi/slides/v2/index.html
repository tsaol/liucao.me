02 · 什么才算 RSI

权威定义:能完全自主地造出自己的继任者

「把这个趋势推到足够远、给足够多的算力,它指向一个能完全自主地设计和开发自己继任者的 AI 系统。这叫递归自我改进。我们还没到那一步,它也不是必然的。」

Anthropic Institute · When AI builds itself(原文英文,此处为翻译)

所以今天大家说的「自我进化」,大多是这条路上的早期几步,不是终点。

怎么说

用前沿实验室自己的定义,别用我的。注意它的两个关键词:「完全自主」「继任者」。

停顿

念到「我们还没到那一步」停。

02 · 什么才算 RSI

只靠迭代,不是 RSI

  • 进化:这一次的产物变好了
  • 自进化:被接受的改进留下来、下次复用
  • 元进化:「怎么改进」本身也在变
  • RSI:改进跨轮次继承,而且让后面的改进变得更好

图源:Li、Chen 等(哈工大深圳、港大、新加坡国立)《Towards AI That Improves Itself: A Survey of RSI》Figure 3,版权归原作者。

怎么说

图底部那句话是重点:「只靠迭代不是 RSI,被接受的改进必须带进后面的改进循环。」

停顿

指着四个阶段,从左往右讲,停在「RSI」那一格。

可能的问题

「prompt 自动优化算不算?」—— 一般在「进化」或「自进化」,不到 RSI。

02 · 它在哪里

在「AI for X」里:X = AI 自己,而且是乘数

  • AI for Science / Math / Code 改的是外面的问题
  • AI for AI 改的是做 AI 这件事本身
  • 回路闭合:更好的 AI → 更大的「研发人力」→ 更好的 AI
  • 所以它会放大所有别的 X

图源:Chan、Pachocki、Hinton、Horvitz、Bengio、Clark、Clune 等《What if automating AI R&D triggers an intelligence explosion?》Figure 2,CC BY 4.0。

怎么说

箭头上那句「Improves & Multiplies」就是乘数的意思。这篇论文作者里有 OpenAI 首席科学家、Hinton、Bengio、微软的 Horvitz。

可能的问题

「会不会无限加速?」—— 论文也列了四种摩擦:收益递减、算力和数据、难自动化的任务、耗时的流程。

红线

不要替论文下「会发生」的结论,它说的是「可能」。

02 · 走到哪一级了

五级自主:今天的产品停在 L2

L1 执行 → L2 策略(AI 选改法,目标和验收由人定)→ L3 经验 → L4 部署 → L5 元改进。图源:Tang、Zhou 等《The Last AI Built by Humans》Figure 1,CC BY-NC-ND 4.0。注意:图中 AlphaEvolve 在 B0(只在一次任务里迭代)。

怎么说

三家云的 agent 优化器都在 L2:人给目标和打分,AI 选改法。L5 没有人做到。

停顿

指出 AlphaEvolve 在 B0:改的是你的代码,不是它自己。这一点很多人会意外。

可能的问题

「那 AlphaEvolve 不算 RSI?」—— 它本身不算;拿它来改 AI 自己的东西、并且结果带进下一轮,才往 RSI 走。

02 · 谁掌握决定

AI4AI:看哪个决定是 AI 做的

  • L1:AI 定方向(往哪找)
  • L2:AI 定空间(能改什么)
  • L3:AI 定评测(什么算好)
  • FunSearch、AlphaEvolve 只是 L1;Eureka、Constitutional AI 是 L3,但 L3 ≠ 全自主
  • 怎么判断:反事实检验—— 换掉 AI 那部分,结果变不变

图源:Liu、Wang、Hu 等(南开、中关村学院、西安交大等)《AI4AI: Toward AI-discovered Superintelligence》Figure 1。解读见 liucao.me/rsi/ai4ai/

怎么说

这把尺子看「控制从哪来」,不是能力。很多看起来很自动的系统,关键决定其实还在人手里。

可能的问题

「和五级自主那张图冲突吗?」—— 不冲突,两把尺子:一个看谁做决定,一个看自主程度。

03 · 各框架站在哪

不同流派,站在不同的格子

流派(代表)核心在思路
进化引擎(AlphaEvolve、OpenEvolve、ShinkaEvolve)③可改的代码 + 打分函数,大规模搜索;评测交给用户
自修改 agent(DGM、HyperAgents、STOP)②③agent 改自己的代码,少数连「改进器」也改
提示词与流程优化(DSPy、GEPA、AFlow)③提示词和工作流当参数,用验证集挑候选
云厂商托管(AgentCore、Foundry)③⑤⑥从生产轨迹改,重点是安全上线
多 agent 写软件(MetaGPT、Cursor、Claude Code 团队)④分工把软件做出来,团队不改进自己
Argus(原型)④⑤⑥引擎借用,门禁自建 + 隔离 + 回放

完整的逐框架对照(20+ 个框架)见 liucao.me/rsi/argus/。能力标注依据 2026-11-18 对官方仓库和文档的调研。

怎么说

一句话:③ 最拥挤,⑤ 最稀缺。大多数框架优化的是「你给的分数」。

可能的问题

「哪个开源引擎能直接用?」—— OpenEvolve、ShinkaEvolve、GEPA、DSPy 都是宽松许可;HyperAgents 不能商用,autoresearch 没有许可证。

红线

表里「没有」多指「文档没提」,不要说成别人一定没有。

04 · 谁来验证

「变好了」要过三关

第一关

不是运气

基线重复跑几次,得到噪声范围;提升要超出噪声(配对 bootstrap)

第二关

不是多花钱

给原系统同样的预算(比如多试几次取最好),新版本还要更好

第三关

不是钻空子

优化过程从没见过的留出集;逐条查退化;最后人审

Goodhart:优化器越强,越会钻评测的漏洞。Google 的教程里,循环为了「变快」干脆跳过渲染;Weco 测到约 63% 的候选在钻空子。评测是一场军备竞赛。

怎么说

这就是全场主问题「谁来验证」的答案。三关缺一不可。

停顿

讲「跳过渲染」的例子时停一下,通常会有笑声。

可能的问题

「谁做得最完整?」—— 调研里只有 AgentCore 明确写了报告统计显著性 + 每条要人批准;没有一家把「预算匹配基线」当门禁。

05 · 竞争与定位

三家云都在做「agent 自动变好」

各家强项

  • Google:AlphaEvolve 已 GA,托管的算法发现,三家里只有它有
  • 微软:Foundry Agent Optimizer,闭环参考方案写得最细
  • AWS:AgentCore optimization + Evaluations,报统计显著性、每条人批准;Recursive 跑在 AWS

Argus 的位置

  • 不做模型,不重造进化引擎(借用 OpenEvolve / Shinka)
  • 占 ④执行 ⑤门禁 ⑥上线 + 隔离 + 回放
  • 右上角:改进对象是自己、验证又严格 —— 目前很空
打法:不和 AlphaEvolve 比引擎,比闭环和中立 —— 评测、上线前验证、多模型可选,评测和轨迹留在客户自己的账号里。

怎么说

坦白承认 Google 在托管算法发现上领先;我们的长处在验证和上线这一段。

可能的问题

「AWS 有没有对标 AlphaEvolve 的?」—— 公开资料里没有托管服务;可以用开源引擎 + Bedrock + Batch 搭出同样的结构。

红线

不讲任何客户名或内部信息。

05 · 我的判断

看完这些资料,五条判断

  • 价值迁移到评测器:模型和引擎都能换,换不掉的是客户的评测器、留出集和轨迹
  • 评测成本会随优化能力上涨:Goodhart 让评测变成军备竞赛
  • 算力形状在变:从训练的大峰值,到评测的高频长尾(短、并行、要隔离)
  • 落地顺序由验证成本决定:仿真器和数字孪生是前置条件
  • 平台竞争在「可审计的改动」和中立,不在引擎

个人观点。每条的机制、证据和「什么情况下我会错」见 liucao.me/rsi/view/

怎么说

核心论点:RSI 改变的是「改进」的成本结构 —— 以前受限于专家,现在受限于评测器质量和评测算力。

可能的问题

「最可能错的是哪条?」—— 如果出现可靠的学习型验证器,第一到第三条都要改。

红线

明确说是个人判断,不是公司立场。

05 · 回去怎么用

见客户,先问三个问题

1

能自动打分吗?

有没有测试、基准、业务指标

2

有留出集吗?

优化过程从没见过的题

3

上线谁来审?

能不能回滚

值得做,当:基线年花费 × 预期提升% × 可用年数 > 评测成本 + 搭评测的人力 + 上线维护。提升是百分比,成本是绝对值 —— 只在花费大、指标清、评测便宜、能回滚的地方做。

怎么说

三个都没有:先帮客户做评测,别谈自我进化。有一个:做小 PoC。三个都有:上自动优化循环。

可能的问题

「最适合的场景?」—— 有仿真或回测的:供应链、路径、排产、性能优化;公开案例(BASF、FM Logistic、Kinaxis)都在这里。

红线

对客户不用「RSI」这个词卖方案,说「自动优化 + 评测闭环」。

Takeaway

记住四句话

  • RSI 已经在发生,但企业今天能用的是冻结模型、自动改 harness(L1–L2)
  • 只靠迭代不是 RSI:改进要带进下一轮,并让改进者变强
  • 生成已经不稀缺,可信的评测才稀缺(③ 拥挤,⑤ 稀缺)
