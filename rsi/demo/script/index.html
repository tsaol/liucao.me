Harness Self-Evolution · 演讲稿

S0 45-60 秒 开场 · 建立场景 Demo 还没点
"我们今天要优化的是一个 电商商品搜索 agent —— 用户输入 query · 它返回 top-5 商品排序。 现在长这样：一个 60 行的 Python search() 函数、BM25 baseline、命中率 30%。 我们不动 Claude 一分权重 · 让它一代一代重写这个 search() · 用 ShinkaEvolve 引擎 · 目标 60~120 秒内冲到 90%+。"
承接的两个真问题（给老板看的）

  • AI 改代码之后 · 怎么证明是真进步不是背答案？
  • 常规命中率评测扛不住这两个问题 · demo 演一个能同时回答的评测系统

S3 20-40 秒 AI 针对错题重写代码 · 🟣 Propose stage=querying · 最长的一段
"这一步最花时间 · AI 读了 31 题的错题清单后要写出改进方案。 看右侧 · 已经生成 N bytes 的 diff。等大概 20-40 秒。"
这 30 秒讲什么 · 4 个选择
  • 讲 harness vs prompt：AI 改的是"代码"不是"提示词" · 更彻底 · git 能追
  • 讲 fine-tune vs 进化：一次 RL $500k · 一次 harness 进化 $50 · 便宜千倍
  • 讲 selection bias：这只是 31 题概念演示 · 生产用得 N ≥ 200 每档
  • 讲 monkey-patch 3 处：ShinkaEvolve 不完美 · 我们打了 3 处补丁才跑通
第 3 节点脉冲 · "AI 针对错题重写代码 → 反馈闭环" · bytes 计数器跳
Bedrock 生成 diff 大概 500-3000 bytes · Opus 4.8 一次约 $0.10
S4 15-25 秒 应用 patch + 跑评测 · 🟠 Apply → 🟢 Verify stage=applying → evaluating
"AI 返回了 diff · 现在应用到父代 · 生成新 Python。然后跑评测 —— 31 公开题 + 5 hold-out + 31 typo 三套评测都要跑 · 才能算 gate。"
三道防作弊门
  • 公开 31 题：AI 看得到的 · 主分
  • Hold-out 5 题：AI 从头到尾看不到 · 抓死记硬背
  • Typo 31 题：每个词随机换字符 · 抓查表小抄（`apple → aplpe`）
  • 综合分 = 0.7 × 公开 + 0.2 × hold-out + 0.1 × typo − 代码惩罚
第 4/5 节点激活 · 评测进度条推 · "生成下一轮错题" 徽章高亮
31 + 5 + 31 = 67 次搜索每一代 · 每代评测约 15-25 秒
S5 5 秒 综合评分 · Gate 判决 · 🔴 Commit stage=scoring
"综合分算出来了 · > 0 就晋升。这是 Karpathy 的 autoresearch 那套 "keep or discard" 门控 · 但我加了防作弊层。"
备用点
  • PPT slide 11 的 5 步循环 · 就是这一整套
  • Gate 拒绝的例子：Harvey R4 涨 0.6pp 但 tokens +46% 被成本罚拒绝
第 6 节点脉冲 · NDCG/combined 数字缓动出现 · "✓ 晋升" 或 "✗ 拒绝"
S6 15-20 秒 第一个 Gen 卡出来 · 数字变化 generation_done · Gen 1 卡片出现

这里最关键 · 别错过
  • 数字是从 0 缓动上去的 · 让观众盯着看数字变
  • 综合分构成条 4 段：绿(公开) + 紫(hold-out) + 蓝(抗干扰) − 红(代码惩罚)
  • 说明 hold-out 也涨了 · 说明 不是死记硬背 · 是真泛化
  • 如果观众问"怎么证明不是运气"：加载 3 次同样结果就行 · 提 CI
