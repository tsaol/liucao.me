核心闭环六块业务能力
E
①
定义目标与评测
什么算「做完」、什么算「更好」:验收测试、评测集、指标
S
②
划定可改范围
允许改哪些东西:代码块、提示词、工具描述、skills、团队结构
D
③
生成与选择改动
往哪个方向改:proposer 写改动,搜索算法挑候选
④
执行
把候选真的跑起来:单 agent,或一个多 agent 团队
⑤
评测与晋升门禁
证明真的更好:不是运气、不是多花钱、不是钻空子
⑥
上线与治理
审批、A/B、版本、回滚;改好的版本进入下一轮
下一轮:改好的版本成为新起点
贯穿能力
隔离与安全:不可信的代码在哪里跑、拿不拿得到凭证、能不能改评测
观测、记账与回放:每一步做了什么、花了多少钱、能不能回到任一时刻
基础
模型:Claude、Gemini、GPT、开源模型(多数框架冻结模型,只改外层)
算力与沙箱:托管 runtime、容器、microVM、批量评测集群

三、Argus 在哪里

作者判断
Argus 不做模型,也不重造进化引擎;它的位置是 ④执行 + ⑤门禁 + ⑥上线 + 隔离 + 回放 这一段 —— 一个「带严格门禁的 AI 研发试验场」

看图要点

  • 每个流派管的是不同的块:进化引擎和提示词优化管 ③,多 agent 框架管 ④,云厂商管 ⑤⑥,评测基础设施管 ④⑤ 的「跑起来」。
  • ③ 最拥挤,⑤ 最稀缺:大多数框架优化的是「你给的分数」,很少同时处理噪声、预算和捷径。调研里只有 AgentCore 明确写了报告统计显著性;没有一家把「预算匹配基线」当门禁。
  • 隔离普遍偏弱:多数开源项目只有 Docker 或一段「会执行不可信代码」的警告;「沙箱里没有凭证 + 模型调用走签名记账代理」在调研里没看到别家这样做。
  • 多 agent 协作的思路不同:MetaGPT / ChatDev 是预设角色流程,Cursor 和 Claude Code 给任务树或任务列表,Argus 只给空数据库让团队自己设计 —— 这是它的实验特点。
  • Argus 的定位:④⑤⑥ + 隔离 + 回放的集成;③ 借用开源引擎(OpenEvolve、ShinkaEvolve、GEPA 等,注意许可证);和云厂商托管优化最接近,但门禁更严、而且能把自己的团队当作改进对象(右上角)。
