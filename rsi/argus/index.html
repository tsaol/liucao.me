E
①
定义目标与评测
什么算「做完」、什么算「更好」:验收测试、评测集、指标
S
②

④
执行

⑤
评测与晋升门禁
证明真的更好:不是运气、不是多花钱、不是钻空子
⑥
上线与治理
审批、A/B、版本、回滚;改好的版本进入下一轮
下一轮:改好的版本成为新起点
贯穿能力

基础
模型:Claude、Gemini、GPT、开源模型(多数框架冻结模型,只改外层)
算力与沙箱:托管 runtime、容器、microVM、批量评测集群

三、Argus 在哪里

作者判断
Argus 不做模型,也不重造进化引擎;它的位置是 ④执行 + ⑤门禁 + ⑥上线 + 隔离 + 回放 这一段 —— 一个「带严格门禁的 AI 研发试验场」

想看 Argus 自己怎么工作、2 到 128 人的实验数据和结论 → Argus 介绍

看图要点

  • 每个流派管的是不同的块:进化引擎和提示词优化管 ③,多 agent 框架管 ④,云厂商管 ⑤⑥,评测基础设施管 ④⑤ 的「跑起来」。
  • ③ 最拥挤,⑤ 最稀缺:大多数框架优化的是「你给的分数」,很少同时处理噪声、预算和捷径。调研里只有 AgentCore 明确写了报告统计显著性;没有一家把「预算匹配基线」当门禁。
  • 隔离普遍偏弱:多数开源项目只有 Docker 或一段「会执行不可信代码」的警告;「沙箱里没有凭证 + 模型调用走签名记账代理」在调研里没看到别家这样做。
  • 多 agent 协作的思路不同:MetaGPT / ChatDev 是预设角色流程,Cursor 和 Claude Code 给任务树或任务列表,Argus 只给空数据库让团队自己设计 —— 这是它的实验特点。
  • Argus 的定位:④⑤⑥ + 隔离 + 回放的集成;③ 借用开源引擎(OpenEvolve、ShinkaEvolve、GEPA 等,注意许可证);和云厂商托管优化最接近,但门禁更严、而且能把自己的团队当作改进对象(右上角)。

四、Argus 和 OpenEvolve 的区别

对照上面的六块能力
对比项OpenEvolveArgus
覆盖哪几块核心是 ③ 生成与选择改动;① 打分函数和 ② 可改的代码块由用户提供;④⑤⑥ 基本不管核心是 ④ 执行、⑤ 评测与晋升门禁、⑥ 上线与治理,加上隔离和回放;③ 借用开源引擎
改什么一段代码(用 EVOLVE-BLOCK 标记),支持多种语言agent 的提示词、工具描述、skills(清单规定可改范围);之后还要改自己团队的工作方式
怎么生成和挑选多个模型生成 diff;MAP-Elites + 岛屿种群、分层评测、错误反馈、全部可设种子复现Claude Code 读失败轨迹后修改,必须写明依据和风险;选父代方法简单,计划借用引擎
怎么算「更好」你给的打分函数分数更高要证明三件事:不是运气(重复跑出噪声分布)、不是多花钱(预算匹配基线)、不是钻空子(proposer 看不到的 held-out + 逐条查退化);最后人工批准
在哪里跑默认在用户自己可信的环境;提供 Docker 镜像,文档未讲不可信代码的隔离沙箱里没有凭证;模型调用走代理签名、按 agent 记账;守卫和判分双容器防作弊
单个还是团队一个搜索循环还有 Swarm:一群 agent 自己组织起来写软件
上线输出最好的程序,由用户自己处理审批、版本、一键回滚;全程可回放
成熟度成熟开源项目,Apache 2.0,v0.4.1(2026-11-02),约 7.8k 星,被很多论文引用私有原型:Swarm 已实测,Evolve 只有方案
两者不是二选一,而是互补:OpenEvolve 回答「怎么找到更好的版本」,Argus 回答「怎么证明它真的更好,并且安全地用起来」。合理的分工是引擎借用 OpenEvolve,门禁、隔离和回放用 Argus 自己的。 详见 Argus 介绍。
