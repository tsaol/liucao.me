我的判断 · 站在 SA 的角度看 RSI

看完 RSI 全景、资本视角、AlphaEvolve 详解 和那些论文之后,作者自己的结论。这一页全部是判断,不是事实;每条都写了依据和把握程度,方便你不同意时回去查原始资料。整理于 2026-11-18。

一句话:RSI 是真的,但企业今天能用的是它的「小版本」—— 冻结模型、自动改 harness 和算法。生成已经不稀缺,稀缺的是可信的评测。SA 最有价值的事,是帮客户先把「怎么打分」建起来,再谈自我改进。
把握程度:高 多个一手来源指向同一结论;中 有证据,但可能变化;低 主要是推测,值得持续观察。

① 对这个领域的判断

  • 「AI 帮着造 AI」已经发生,但离「AI 自己造 AI」还远。高
    依据:Google 生产代码超过 75% 由 AI 写,但约 88% 仍需人反复引导;METR 评估 Anthropic 研发速度约 2 倍;OpenAI 明说现在不该做全自主 RSI。三家前沿实验室的说法方向一致,只是快慢不同。
  • 企业能落地的是图 5 的 L2:人定目标和打分,AI 选改法。高
    依据:Google、微软、AWS 的产品(AlphaEvolve、Foundry Agent Optimizer、AgentCore optimization)都停在这一级;L3 以上只在研究里。客户说「自我进化」时,十有八九指的是这一级。
  • 瓶颈是验证,不是生成。高
    依据:本场 demo 一轮成本 97.7% 在评测;AlphaEvolve 的生成是托管的,评测在客户那边;几乎所有新论文(SoL-Pi、TRUST、HarnessDev)都在解决「怎么验证」。
  • 真实提升多在个位数到两位数百分比,不是魔法。高
    依据:FM Logistic 10.4%、Coolblue 5%、JetBrains 15–20%、Google 的 skill 优化约 5%、Borg 0.7%。在已经很优化的系统上,这些已经很值钱;但对客户要讲「可验证的小胜」,不要讲「自我进化的 AI」。
  • 资本热度领先于技术进展。中
    依据:几家没有收入的新实验室估值 40 亿到 500 亿美元,成绩多为自报;一年后可能有一部分转向或被收购。热度本身不是证据。

② 对客户怎么讲

  • 先问诊,三个问题 高:
    1. 你有没有能自动打分的方法(测试、基准、业务指标)?
    2. 你有没有留出集(优化过程从没见过的题)?
    3. 改动上线前谁来审,能不能回滚?
    三个都没有:先做评测,不谈自我改进。有一个:做小范围 PoC。三个都有:可以上自动优化循环。
  • 挑「能打分」的问题做 PoC。高
    适合:性能优化(kernel、查询、视频处理)、调度和路径、需求预测、供应链模拟、芯片验证、agent 的 prompt / skill。不适合:没有基准、质量靠主观判断、反馈要几个月才回来的问题。
  • 先改 harness,不改权重。高
    依据:只跑推理、便宜、随时能回滚;demo 0.42 → 0.94 就是冻结权重做到的。改权重(微调、RL)留到 harness 的空间用完以后。
  • 把「防刷分」写进方案。高
    依据:Google 视频教程里循环会「跳过渲染来变快」;Weco 测到 63% 的钻空子。方案里要有:隐藏题、换说法重考、能力底线、成本罚分、人审。
  • 不要用「RSI」这个词卖方案。中
    依据:它在美国已经是监管和舆论的敏感词(有禁止法案提案);对企业客户,「自动优化 + 评测闭环」更准确,也更容易过内部审批。

③ 竞争怎么看

  • 承认 Google 在「托管的算法发现」上领先。高
    依据:AlphaEvolve 已 GA,有 BASF、Klarna、JetBrains 等公开案例,还有 Cloud Batch 扇出评测;微软和 AWS 目前没有对应的托管服务。
  • 不和 AlphaEvolve 比引擎,比闭环和中立。中
    理由:进化引擎有成熟的开源实现(ShinkaEvolve、OpenEvolve,结构和 AlphaEvolve 一样);客户真正缺的是评测、上线前验证(离线评测 + A/B)、多模型可选、和现有系统的集成。AWS 的 AgentCore optimization / Evaluations 正好在这一层。
  • 「生成在云上、评测在你那边」对谁都成立。中
    理由:AlphaEvolve 的评测本来就跑在客户自己的算力上;用开源引擎 + Bedrock + AWS Batch / Spot 能搭出同样的结构,而评测往往是成本大头。
  • 微软的产品闭环做得细,别低估。中
    依据:Foundry 的「生产轨迹 → 人工标注 → 优化 → PR 人审 → 回归集 → 灰度」是三家里写得最完整的参考方案。

④ 基础设施的机会

  • 评测算力是一种新负载。高
    特点:大量短小、并行、可中断的任务,每个候选一个沙箱,跑完就丢。适合 Spot、Batch、快速启动的 microVM;Google 专门做了 Agent Compute Engine,说明大厂也这么看。
  • RSI 公司要的不只是 GPU。中
    依据:实验编排、沙箱、评测集群、实验记录存储、最新加速芯片的快速交付;kernel 自动优化还可能让模型更容易移植到非 CUDA 芯片。
  • 跟着融资看需求。中
    依据:新实验室通常在融资后 1–3 个月签下主要算力合同,首轮相当大一部分会流向一朵云(Recursive 约 63%、Mirendil 约一半)。融资新闻就是需求信号。
  • 治理会从「负担」变成「需求」。中
    依据:监管提案要求审计、隔离、kill switch;实验室和研究者自己也在做(OpenAI 对新模型做全轨迹监控;NVIDIA SoL-Pi 的留出结果绝不回流给优化器)。能把这些做成现成能力的平台会更好卖。

⑤ 中国区的判断

  • 本土 RSI 创业公司离海外云比较远。中
    依据:多为天使 / Pre-A,出钱的主要是地方国资和美元基金,算力伙伴没公开、很可能在用国产算力。
  • 更实际的机会在两类客户。中
    一是出海企业的评测、推理、沙箱;二是传统行业的「算法优化」 —— 供应链、物流、制造排产,这正是 AlphaEvolve 公开案例最多的地方(BASF、FM Logistic、Kinaxis),也是本土客户最容易算清 ROI 的地方。
  • 国内的研究很活跃,值得拿来讲。高
    依据:字节、华为、上海 AI Lab、DeepSeek 等都有 harness 自进化和自我验证的工作(见 资料包 · 国内成果),而且重点同样在「怎么验证」。

⑥ 如果是我,接下来会做什么

  1. 准备一个「评测先行」的演示:用现有 demo,讲清楚 0.42 → 0.94 是怎么来的,重点放在评测、晋升门和成本,而不是「AI 自己变聪明」。
  2. 找一个能打分的客户问题做小 PoC:优先选供应链、路径、性能优化这类有明确指标的问题,先用两周把评测和留出集建好。
  3. 做一张竞品对比卡:AlphaEvolve / Foundry Agent Optimizer / AgentCore optimization 各自改什么、怎么验证、在哪里跑评测(素材在 全景 ③)。
  4. 每月更新一次观察清单(见 ⑦)。

⑦ 接下来半年要看什么

  • 微软、AWS 会不会推出对标 AlphaEvolve 的托管「算法发现」服务。
  • Anthropic 上市后,季度报告里怎么披露 AI 研发加速和 RSI 风险。
  • METR 这类第三方评估是否覆盖更多实验室,证据是否更透明。
  • 美国禁止或管控 RSI 的法案是否真的推进。
  • 新实验室能否拿出可独立验证的成果,而不只是自报的 benchmark。
  • 企业案例里的提升幅度是在变大,还是一直停在个位数到两位数。

这些判断会随新资料更新。如果你有不同看法或新证据,欢迎指出。
