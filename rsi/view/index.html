我的判断 · 站在 SA 的角度看 RSI

看完 RSI 全景、资本视角、AlphaEvolve 详解 和那些论文之后,作者自己的结论。这一页全部是判断,不是事实。每条都写了:为什么会这样、证据是什么、对 SA 意味着什么、什么情况下我会错。整理于 2026-11-18,2027-05 回头打分。

核心论点:RSI 真正改变的不是「AI 有多聪明」,而是「改进」这件事的成本结构 —— 以前改进受限于稀缺的专家,现在受限于评测器的质量和评测的算力。所以价值会从模型流向评测器,算力需求会从「训练的大峰值」变成「评测的高频长尾」,而竞争会落在谁托管评测、谁管住改动。

判断 1:价值正在从「模型」迁移到「评测器」

  • 机制:在一个「冻结模型、自动改代码 / harness」的循环里,三样东西里有两样已经可以替换 —— 生成用的模型可以换(Gemini、Claude、开源),进化引擎是开源的(OpenEvolve、ShinkaEvolve 和 AlphaEvolve 结构一样)。唯一换不掉的,是客户自己的评测器、留出集和历史轨迹,因为它们编码了「这家公司认为什么是更好」。
  • 证据:AlphaEvolve 的官方设计是「生成在 Google Cloud,评测在客户那边」,而且明说「不运行你的代码」;BASF 的关键工作是先用三年历史数据定义「模拟和现实有多接近」这个打分;JetBrains 说「工程师仍然掌握基准、评审和发布决定」。
  • 对 SA 的意义:客户粘性不在「用谁的模型生成」,而在评测在哪里跑、轨迹和留出集存在哪里。帮客户把评测器、数据集和轨迹建在自己账号里,比推某个模型更持久。反过来说,谁拿走了评测器,谁就拿走了这个循环。
  • 我会错,如果:托管服务开始提供「行业标准评测集」并让客户依赖它们(评测器本身被平台化),那粘性会回到平台一侧。

判断 2:算力需求的形状在变 —— 从「训练峰值」到「评测长尾」

  • 机制:每一轮进化都要把几十到几百个候选各跑一遍。这些任务小、短、高度并行、可以被打断、每个都要隔离,而且很多是 CPU 任务(编译、仿真、跑测试),不只是 GPU。冷启动时间、按秒计费、Spot 能不能拿到、隔离够不够强,会比「有多少张 GPU」更重要。
  • 证据:本场 demo 一轮成本 97.7% 在评测;Google 专门做了给 agent 用的 microVM 服务(Agent Compute Engine,强调「评测扫描不等基础设施」),又把 AlphaEvolve 接到 Cloud Batch 扇出几百个评测;沙箱成了独立的生意(Modal 的沙箱业务据报年化约 3 亿美元)。
  • 对 SA 的意义:RSI 类负载的架构评审要问的不是「训练集群多大」,而是「一万个十秒钟的隔离任务怎么调度、多少钱、多快起来」。云厂商现有的小粒度原语(轻量虚拟机、Batch、Spot、无服务器)会是隐藏的竞争力。
  • 我会错,如果:评测越来越多地由「学出来的验证模型」完成(在 GPU 上打分,而不是真的去跑代码),需求形状会回到 GPU 推理。

判断 3:Goodhart 定律是这个领域的物理定律 —— 评测成本会随优化能力一起上涨

  • 机制:优化器越强,越会找到评测的漏洞(「指标一旦成了目标,就不再是好指标」)。所以评测不是一次性的投入,而是一场军备竞赛:优化能力每上一个台阶,评测就要加隐藏题、换题、加约束。评测预算应该跟着优化强度一起涨,而不是固定。
  • 证据:Google 的视频教程里,进化循环会「跳过渲染来变快」,只能加画质门槛;Weco 测到约 63% 的候选在钻空子;NVIDIA SoL-Pi 要把「能力底线」藏起来、不让被优化的一方看到;字节 HarnessDev 发现 agent 自己的评判几乎预测不了下一轮的提升。
  • 一个推论:进展会集中在评测本身很难被骗的领域 —— 数学(形式化证明)、芯片(等价性验证)、kernel(真机计时)。这也解释了为什么 AlphaEvolve 最硬的成果都在这些地方。
  • 对 SA 的意义:可以给客户提供一种新服务 ——「给你的评测器做红队」:专门找评测的漏洞,像安全团队找系统漏洞一样。评测运维(EvalOps)会像 SecOps 一样变成持续的工作。
  • 我会错,如果:出现通用、可靠、便宜的自动验证方法(不靠人设计评测也能防刷分),那评测就不再是瓶颈。目前没看到迹象。

判断 4:落地顺序由「验证的成本和速度」决定,不是由「AI 在哪最聪明」决定

  • 机制:一个问题能不能被自动改进,取决于两件事:打一次分要多少钱、多久能知道结果。按这两项排序,大致是:kernel / 编译器(秒级、精确)→ 数学(形式化)→ 调度、路径、排产(有仿真器)→ 预测(要回测,还得等真实数据)→ 产品体验(几周、噪声大)。
  • 证据:Jeff Dean 说「无限加速不现实」,因为实验需要物理时间;AlphaEvolve 的企业案例几乎全是有仿真或回测的问题(BASF 供应链孪生、FM Logistic 路径、Kinaxis 预测、Coolblue 需求预测)。
  • 一个推论:仿真器和数字孪生是 RSI 的前置条件。BASF 的第一步不是优化,而是建一个能和历史数据对上的数字孪生。所以 RSI 会拉动仿真和 HPC 需求 —— Google 在超算大会 SC26 上推 AlphaEvolve,就是这个信号。
  • 对 SA 的意义:挑客户时,先问「你有没有仿真器 / 回测 / 自动化测试」。没有的,第一个项目是帮他建仿真或评测,而不是直接上优化。这也是最自然的 HPC 和数据平台切入点。
  • 我会错,如果:基础模型能可靠地「预测实验结果」,替代真实仿真。目前论文显示这类预测还不可靠。

判断 5:大厂卖的不是「自我改进」,是「可审计的自动改动」

  • 机制:企业怕的不是改得不够好,而是改坏了不知道、出了事说不清。所以三家产品都把循环包装成「人在环路」:离线评测、A/B、开 PR 给人审、回归集把关、灰度上线。真正的产品是改动的治理 —— 版本、来源、谁批准的、怎么回滚。
  • 证据:微软的参考方案是「生产轨迹 → 人工标注 → 优化 → PR 人审 → 留出回归集 → 灰度」;AWS AgentCore 是「离线批量评测 + 线上 A/B,赢了才上线」;AlphaEvolve 的客户原话是「工程师掌握发布决定」。
  • 对 SA 的意义:不要把它讲成 AI 新功能,要讲成「给 agent 和算法的 CI/CD」,接进客户已有的代码评审、审批和变更管理流程。谁能和客户的变更流程集成得最好,谁就赢 —— 这比优化效果差几个百分点更重要。
  • 我会错,如果:企业开始接受「无人审批的自动上线」(比如低风险场景先放开)。那时竞争会回到「谁的优化效果更好」。

判断 6:RSI 的第一批商业成果是「省算力」,而这会扩大、而不是减少用量

  • 机制:最早落地的成果几乎都是效率:Borg 回收 0.7% 算力、Gemini 训练快 1%、FlashAttention 快 32.5%、SoL-Pi 的 token 少约 45%、HarnessMM 少 30%–88%。单个任务更便宜了,但历史上效率提升往往带来更多使用(杰文斯悖论):更便宜的推理会被用在更多地方。
  • 对 SA 的意义:客户用这类工具后,某些负载的账单会下降。主动帮客户做这件事,比被动等竞争对手来做好 —— 省下来的钱和建立的信任,通常会变成新的负载。
  • 我会错,如果:需求已经饱和,省下的算力没有新用途。目前 AWS 说自己的产能到 2027 年基本卖光,Google、微软的资本开支也没有下调,看不到饱和。

判断 7:「模型中立」是结构性优势,但正在被追平

  • 机制:前沿实验室的条款不让客户用它们的服务训练竞争模型;a16z 投 Mirendil 的理由就是「结构上必须有一家独立公司」。同样的逻辑适用于云:不绑定自家模型的平台,天然适合让第三方在上面跑 RSI 循环。
  • 证据和反证:Recursive 把研究循环放在 AWS;但 Google Cloud 11 月已经说自己是唯一同时提供三家主要闭源模型的大云 —— 中立这张牌在被追平。AlphaEvolve 托管版仍然只用 Gemini。
  • 对 SA 的意义:中立要讲具体:同一套评测、同一批任务,换模型对比只需要改一个参数;评测和轨迹留在客户账号里,不被某家模型锁住。光说「我们模型多」已经不够。
  • 我会错,如果:托管 AlphaEvolve 开放第三方模型,或者客户发现「最好的生成模型」只有一家、中立没有意义。

判断 8:人最后交出去的是「评测权」—— 这也是 SA 最该练的能力

  • 机制:AI4AI 综述把控制权分成三步交给 AI:先交出搜索方向,再交出搜索空间,最后才交出评测信号(L3)。今天的产品都停在评测权还在人手里。也就是说,未来几年人的杠杆会集中在「定义什么是好」上。
  • 对 SA 的意义:会写评测的人,会比会写 prompt 的人更值钱。SA 能给客户最有用的技能转移,是教团队设计评测:怎么选指标、怎么做留出集、怎么防刷分、怎么算评测成本。这比讲任何一个产品都更持久。
  • 我会错,如果:L3(AI 自己定评测)在企业场景里可靠地落地。那就是真正的 RSI 了,本页大部分判断都要重写。

判断 9:资本结构是「云在给 RSI 的需求做看涨期权」,SA 要看懂这个时间窗口

  • 机制:新实验室融到的钱,相当大一部分会在一年内变成某一朵云的长期算力合同(Recursive 约 63%、Mirendil 种子轮约一半)。云厂商签这些合同,等于押注「RSI 研究会持续消耗大量算力」。如果研究顺利,需求会继续涨;如果不顺,这些公司会转向或被收购,合同会被重谈。
  • 对 SA 的意义:新实验室通常在融资后 1–3 个月就选定算力伙伴,而且一旦把评测和数据流水线建在某朵云上,很少再迁。窗口很短,而且是一次性的。
  • 我会错,如果:实验室普遍采用多云、可迁移的架构,或者算力变成纯商品、随时换。目前的大单都是多年期、单一云。

这些是作者的主观概率,目的是让判断可以被检验。2027-05 做中期回顾,2027-11 正式打分。

我最没把握的地方

  • 前沿实验室内部到底多快:最关键的证据(实验室内部的加速数据)大多被涂黑或不公开。如果内部已经接近 L3,本页对「企业停在 L2」的判断会很快过时。
  • 评测会不会被模型「学会」:如果出现可靠的学习型验证器,判断 1、2、3 都要改。
  • 中国区:本土 RSI 公司和大厂的算力、技术路线公开信息很少,判断主要靠推测。
