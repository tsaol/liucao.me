我的判断 · 站在 SA 的角度看 RSI

看完 RSI 全景、资本视角、AlphaEvolve 详解 和相关论文之后,作者自己的结论。整理于 2026-11-18;2027-05 中期回顾,2027-11 打分。

声明:这一页是作者的个人观点,不代表任何雇主或公司的立场,也不是投资建议。所用资料全部来自公开来源。
核心论点:RSI 真正改变的不是「AI 有多聪明」,而是「改进」这件事的成本结构。以前,改进受限于稀缺的专家;现在,改进受限于评测器的质量和评测的算力。由此推出:价值从模型流向评测器;算力需求从「训练的大峰值」变成「评测的高频长尾」;平台竞争落在谁托管评测、谁管住改动。
读法:每条判断都写了 机制(为什么会这样)、证据、对 SA 的意义、我会错,如果。标 推测 的部分没有直接证据,是推理出来的。

先说证据的局限

  • 企业案例有幸存者偏差:BASF、Coolblue、FM Logistic 这些数字都是客户和 Google 自己公布的成功案例。失败、放弃的项目不会被公开,所以真实的平均提升很可能比公开案例低。
  • 前沿实验室的关键数据大多不公开:METR 评估 Anthropic 时,最关键的证据被涂黑了;各家「AI 写了多少代码」都是自报。
  • 评测成本的数字样本很少:本页反复用到的「一轮约 856 美元、97.7% 花在评测」来自本场 demo 的一次测算,不是行业统计。方向我有把握,具体比例因场景而异。

判断 1:价值正在从「模型」迁移到「评测器」

  • 机制:在「冻结模型、自动改代码 / harness」的循环里,三个部件有两个可以替换 —— 生成模型可以换(Gemini、Claude、开源),进化引擎是开源的(OpenEvolve、ShinkaEvolve 和 AlphaEvolve 结构相同)。换不掉的是客户自己的评测器、留出集和历史轨迹,因为它们写下了「这家公司认为什么是更好」。
  • 长期看也是这样:AI4AI 综述把控制权分三步交给 AI —— 先交出搜索方向,再交出搜索空间,最后才交出评测信号。今天所有产品都停在评测权还在人手里。所以未来几年,人的杠杆会集中在「定义什么是好」上。
  • 证据:AlphaEvolve 官方设计是「生成在 Google Cloud,评测在客户那边」,并明说「不运行你的代码」;BASF 项目的关键一步,是先用三年历史数据定义「模拟和现实有多接近」这个分数;JetBrains:「工程师仍然掌握基准、评审和发布决定。」
  • 对 SA 的意义:客户粘性不在「用谁的模型生成」,而在评测在哪里跑、轨迹和留出集存在哪里。帮客户把评测器、数据集、轨迹建在他自己的账号里,比推任何一个模型都持久。SA 最值得练、也最值得教给客户的能力,是设计评测:选指标、做留出集、防刷分、算评测成本。
  • 我会错,如果:平台开始提供「行业标准评测集」并让客户依赖(评测器被平台化);或者 AI 能可靠地自己定评测(AI4AI 的 L3)—— 那就是真正的 RSI,本页大部分判断都要重写。

判断 2:Goodhart 定律是这个领域的物理定律 —— 评测成本会随优化能力一起上涨

  • 机制:「指标一旦成了目标,就不再是好指标。」优化器越强,越会找到评测的漏洞。所以评测不是一次性投入,而是一场军备竞赛:优化能力每上一个台阶,评测就要加隐藏题、换题、加约束。评测预算应该跟着优化强度一起涨。
  • 证据:Google 视频教程里,进化循环会「跳过渲染来变快」,只能加画质门槛(SSIM);Weco 测到约 63% 的候选在钻空子;NVIDIA SoL-Pi 要把「能力底线」藏起来,不让被优化的一方看到;字节 HarnessDev 发现 agent 自己的评判几乎预测不了下一轮的提升。
  • 推论:进展会先集中在评测本身很难被骗的领域 —— 数学(形式化证明)、芯片(等价性验证)、kernel(真机计时)。这正是 AlphaEvolve 最硬的成果所在。
  • 对 SA 的意义:可以给客户做一件新的事 ——给评测器做红队,专门找评测的漏洞,像安全团队找系统漏洞一样。评测运维会像安全运维一样,变成持续的工作,而不是项目开始时做一次。
  • 我会错,如果:出现通用、可靠、便宜的自动验证方法,不靠人精心设计也能防刷分。目前没看到迹象。

判断 3:算力需求的形状在变 —— 从「训练峰值」到「评测长尾」

  • 机制:每一轮进化都要把几十到几千个候选各跑一遍。这些任务小、短、高度并行、可以被打断、每个都要隔离,而且很多是 CPU 任务(编译、仿真、跑测试)。冷启动时间、按秒计费、Spot 能不能拿到、隔离够不够强,会比「有多少张 GPU」更重要。
  • 证据:Google 的 skill 优化一次搜索就跑了「几千次 agent 试验」,每次一个容器;Coolblue 用了约 200 轮迭代;Google 专门做了给 agent 用的 microVM 服务(Agent Compute Engine,强调「评测扫描不等基础设施」),又把 AlphaEvolve 接到 Cloud Batch 扇出几百个评测。沙箱成了单独的生意(据报 Modal 的沙箱业务年化约 3 亿美元,二手)。
  • 一个反直觉的地方:RSI 第一批商业成果几乎都是省算力(Borg 回收 0.7%、Gemini 训练快 1%、FlashAttention 快 32.5%、HarnessMM 每题 token 少 30%–88%)。单个任务更便宜了,但历史上效率提升往往带来更多使用。所以对云来说,它既减少某些负载的账单,又创造新的评测负载。
  • 对 SA 的意义:RSI 类负载的架构评审,要问的不是「训练集群多大」,而是「一万个十秒钟的隔离任务怎么调度、多少钱、多快起来」。现有的小粒度原语(轻量虚拟机、Batch、Spot、无服务器)是隐藏的竞争力。主动帮客户把某些负载做省,比等竞争对手来做好。
  • 我会错,如果:评测越来越多地由「学出来的验证模型」完成(在 GPU 上打分,不真跑代码),需求形状会回到 GPU 推理。

判断 4:落地顺序由「验证的成本和速度」决定,不是由「AI 在哪最聪明」决定

  • 机制:一个问题能不能被自动改进,看两件事:打一次分要多少钱、多久能知道结果。大致排序:kernel / 编译(秒级、精确)→ 数学(形式化)→ 调度、路径、排产(有仿真器)→ 预测(要回测、要等真实数据)→ 产品体验(几周、噪声大)。
  • 证据:Jeff Dean 说「无限加速不现实」,因为实验需要物理时间;AlphaEvolve 的企业案例几乎都是有仿真或回测的问题(BASF 供应链孪生、FM Logistic 路径、Kinaxis 和 Coolblue 预测)。
  • 推论:仿真器和数字孪生是前置条件。BASF 的第一步不是优化,是建一个能和历史数据对上的数字孪生。所以 RSI 会拉动仿真和 HPC 需求 —— Google 在超算大会 SC26 上推 AlphaEvolve,就是这个信号。
  • 对 SA 的意义:挑客户先问「你有没有仿真器 / 回测 / 自动化测试」。没有的,第一个项目是帮他建仿真或评测,而不是直接上优化。这也是 HPC 和数据平台最自然的切入点。
  • 我会错,如果:基础模型能可靠地「预测实验结果」,替代真实仿真。目前这类预测还不可靠。

判断 5:平台竞争不在「引擎」,而在「可审计的改动」和「中立」

  • 机制 1 —— 企业买的是治理:企业怕的不是改得不够好,而是改坏了不知道、出了事说不清。所以三家产品都把循环包装成人在环路:离线评测、A/B、开 PR 给人审、回归集把关、灰度上线。真正的产品是改动的治理:版本、来源、谁批准的、怎么回滚。
  • 机制 2 —— 中立是结构性优势:前沿实验室的条款不让客户用其服务训练竞品(a16z 投 Mirendil 的理由就是「结构上必须有一家独立公司」)。同理,不绑定自家模型的平台更适合让第三方跑 RSI 循环。
  • 证据:微软参考方案「生产轨迹 → 人工标注 → 优化 → PR 人审 → 留出回归集 → 灰度」;AWS AgentCore「离线批量评测 + 线上 A/B,赢了才上线」;Recursive 把研究循环放在 AWS。反证:Google Cloud 11 月已经说自己是唯一同时提供三家主要闭源模型的大云,中立在被追平;但托管 AlphaEvolve 仍只用 Gemini。
  • 对 SA 的意义:不要讲成 AI 新功能,要讲成「给 agent 和算法的 CI/CD」,接进客户已有的代码评审、审批和变更管理。中立要讲具体:同一套评测、同一批任务,换模型对比只改一个参数;评测和轨迹留在客户账号里。
  • 我会错,如果:企业开始接受「无人审批的自动上线」,竞争会回到「谁的优化效果更好」;或者托管 AlphaEvolve 开放第三方模型,中立的差异消失。

判断 6:资本在给 RSI 的算力需求做看涨期权,对 SA 来说窗口短

  • 机制:新实验室融到的钱,相当大一部分会在一年内变成某一朵云的长期算力合同(Recursive 约 63%、Mirendil 种子轮约一半)。云签这些合同,等于押注「RSI 研究会持续消耗大量算力」。研究顺利,需求继续涨;不顺,公司会转向或被收购,合同会被重谈。
  • 证据:Recursive 融资约两个半月后签下 AWS 4.1 亿美元多年协议;Mirendil 种子轮后 6 周签下 Google Cloud 1 亿美元以上。已披露的大单都是多年期、单一云。
  • 对 SA 的意义:融资新闻就是需求信号,决定往往在融资后 1–3 个月内做出。推测一旦评测和数据流水线建在某朵云上,迁移成本会很高,所以这个窗口接近一次性 —— 这一点我没有直接证据,是根据「评测器和轨迹是核心资产」(判断 1)推出来的。
  • 我会错,如果:实验室普遍采用多云、可迁移的架构,或者把算力当纯商品随时换。

反方论证:我可能完全错的两种情景

情景 A:RSI 在企业里「熄火」

  • 会怎样:评测成本涨得比收益快(判断 2 的军备竞赛输了);大多数企业问题没有便宜的仿真器(判断 4 的门槛太高);公开案例之外的项目大多做不出可上线的提升。自动优化变成少数大公司、少数场景的工具,就像今天的运筹优化一样小众。
  • 早期信号:2027 年的新案例仍集中在同一批明星客户;客户 PoC 停在评测阶段做不下去;托管服务的价格开始大幅下调却没带来更多案例。
  • 即使这样,什么还成立:评测和仿真本身仍然有价值(质量保障、回归测试、变更治理);判断 1 和判断 4 在「没有 RSI」的世界里也大体成立。

情景 B:前沿实验室把一切吸走

  • 会怎样:如果头部实验室先做到接近全自动的 AI 研发,它们会把「自动优化」直接做进模型和 agent 里,作为免费功能;企业的 L2 工具和新实验室都失去意义,评测标准也由模型厂商来定。
  • 早期信号:模型厂商的 API 里出现「自带自我优化」的 agent;Anthropic 上市后的披露显示内部已远超 2 倍加速;新实验室开始被大量收购或「授权 + 挖人」(见预测 5)。
  • 即使这样,什么还成立:企业自己的评测器和数据仍然不能外包(判断 1);跑这些模型和评测的算力仍然需要云(判断 3)。变化最大的是判断 5 和判断 6。

客户算账:什么时候值得做

关键关系:提升是百分比,成本是绝对值。所以只有在「基线花费足够大」的地方,自动优化才值得做。

值得做,当:  基线年花费 × 预期提升% × 能用的年数
          >  (候选数 × 每个候选的评测成本) + 搭评测 / 仿真的人力 + 上线和维护成本
  • 同一个百分比,意义完全不同:0.7% 在 Google 全球算力上相当于一大笔钱;对一个每月算力账单 1 万美元的客户,只是每月约 70 美元,搭评测的人力都不够。
  • 评测成本要按「次数」算:公开资料里,一次优化要几十到几千个候选(ShinkaEvolve 约 150 个样本出结果、Coolblue 约 200 轮、Google 的 skill 搜索「几千次 agent 试验」)。如果每个候选都要跑完整的 agent 任务,成本会很快上去;本场 demo 一轮约 856 美元,其中 97.7% 是评测。
  • 一个假设的例子 假设:某个 agent 每月模型调用花 5 万美元。如果像 HarnessMM 那样把每题 token 降 30%,每月省约 1.5 万美元;做 10 轮优化按 demo 的量级约 8,600 美元。不到一个月就回本 —— 前提是质量不降,而这要靠留出集来证明。
  • 反过来的例子 假设:一个每天只跑几百次、每月花几百美元的内部工具,即使提升 30%,也不值得为它搭评测。
  • 对 SA 的意义:先帮客户把这张账算出来,再决定做不做。最值得做的通常是:花费大、指标清楚、评测便宜、改动能回滚的负载。

可以被打分的预测(到 2027-11-18)

#预测概率判定标准
1微软或 AWS 至少一家推出托管的「进化式算法 / 代码优化」服务65%官方宣布(预览或正式版均可)一个服务:用户给种子代码和打分函数,服务用大模型迭代改代码。只改 prompt / skill 的不算。
2公开企业案例的提升仍以个位数到两位数百分比为主75%2027 年内 Google、微软、AWS 官方博客公布的自动优化客户案例里,超过一半的主要指标提升在 5%–25%,且不到四分之一声称「翻倍」以上。
3至少一家大云推出单独计费的 agent 评测沙箱 / 批量评测产品70%有独立的产品名和价格页,用途明确写着运行 agent 或代码评测的隔离环境。
4出现一次因自动优化「钻评测空子」导致的公开生产事故55%主流科技媒体(TechCrunch、The Verge、WIRED 等)或公司自己的事后报告中,明确说是自动优化 / 自我改进循环让指标变好但实际行为变差,并影响了真实用户。
5至少一家估值 40 亿美元以上的 RSI 新实验室被收购、被「授权 + 挖人」或明显转向50%样本为 Recursive、Mirendil、Discovery Loop、Ineffable、Core Automation、Ricursive;「明显转向」指公开宣布放弃自我改进作为主要方向。
6美国通过一部直接限制「自我改进 AI」的联邦法律10%参众两院通过并由总统签署;只是提案或委员会通过不算。
7有企业公开宣布在生产中采用「无人审批、自动上线」的自我改进循环25%非实验、非演示;公司官方说明改动不经人审即上线到真实用户。

这些是作者的主观概率,目的是让判断可以被检验。2027-05 做中期回顾,2027-11 正式打分并公开结果。

我最没把握的地方

  • 前沿实验室内部到底多快:关键数据大多不公开。如果内部已经接近 L3,「企业停在 L2」的判断会很快过时。
  • 评测会不会被模型「学会」:如果出现可靠的学习型验证器,判断 1、2、3 都要改。
  • 中国区:本土 RSI 公司和大厂的算力、技术路线公开信息很少,相关判断主要靠推测。
