开源自进化引擎与行业 demo

给 Agent 自进化 / RSI 动手实验做的调研:除了 ShinkaEvolve,还有哪些开源框架、各自改什么、怎么接 Amazon Bedrock、适不适合 2–3 小时的 workshop;以及行业里大家都认识的 demo。数据来自各项目的 GitHub、PyPI、README、论文和官方博客,核对于 2026-11-24。写「未核实」「没实测」的地方以原文为准。

相关:RSI 分享 · 案例:小红书 × AWS AI Lab Research Agent · AlphaEvolve 详解 · 论文解读
  • 日期：2026-11-24（GitHub 星数、license、最后 push 都是当天用 GitHub REST API 取的）
  • 主引擎：ShinkaEvolve（基线）
  • 方法：GitHub API、PyPI JSON、把 40 个仓库浅克隆下来 grep（bedrock / litellm / anthropic / openai）、读 README 和 docs、用 HF papers API 核对论文标题。实测了 Bedrock 的 OpenAI 兼容端点（见第 2 节）。
  • 原始数据：engines.json（每个项目的字段，加上 demos）
  • 写着“未实测”的，意思是文档或代码里有这条路，但我们没有真的跑过。

1. 结论（先看这里）

换引擎模块，推荐 1–2 个：

  1. OpenEvolve（首选）：7,861 星，Apache-2.0，2026-11-24 还有 push。
  2. 评估器接口和我们的几乎一样：evaluate(program_path) 返回一个 dict，里面有 combined_score，进化区也用 EVOLVE-BLOCK-START/END 标记。我们的 score(program_path) 只要包一行就能用。
  3. pip install openevolve，依赖很轻，只用 CPU。
  4. 方法和 Shinka 不一样（MAP-Elites + island），放在同一道题上对比很好讲。
  5. 缺点：没有原生 Bedrock，只支持 OpenAI 兼容接口。要用 Claude 得先起一个 LiteLLM proxy（见第 2 节）。
  6. GEPA（第二个，换的是“进化对象”）：7,560 星，MIT。
  7. 从“改代码”换到“改 prompt / skill / 配置”。optimize_anything(seed, evaluator, objective) 也能把我们的 score(program_path) 包进去用。
  8. 模型名用 LiteLLM 格式，可以直接写 bedrock/...，不用起 proxy（未实测）。
  9. 已经集成进 DSPy（dspy.GEPA），客户问 DSPy 时能顺着讲。
  10. 备选：SkyDiscover（UC Berkeley，769 星，Apache-2.0）。一条 CLI 里用 --search 就能切换 adaevolve / evox / openevolve / gepa / shinkaevolve，评估器还是 evaluate(program_path) 加 combined_score。从“换引擎”的角度看它最合适，但它在 PyPI 上的情况不清楚，README 只写了 git clone + uv sync，Bedrock 也要走代理。建议讲师先自己跑通一遍，再决定要不要把它放进课程。

可以提，但不要在课上跑：

  • CodeEvolve、LLM4AD（EoH/FunSearch/ReEvo 等的统一平台）、LEVI、DSPy MIPROv2、TextGrad、Trace、ACE（Kayba 版）、Meta-Harness、AHE、DGM、HGM、ADAS、AFlow、AIDE、SICA、EvoAgentX、karpathy/autoresearch。原因各不相同：太重（Docker、SWE-bench、E2B），太贵（DGM 一次完整运行约 2.2 万美元），接口差得太远（DSPy 要把任务重写成程序），或者项目太新、太小。

避开：

  • 停更：OpenELM（最后 push 2023-11）、FunSearch 参考代码（2024-02，不带 LLM 和沙箱）、OpenAlpha_Evolve（2025-05）、PromptBreeder 社区实现（2024-08）。
  • 许可证有问题：Meta AIRA-dojo（CC BY-NC 4.0，不能商用）；Sakana AI Scientist（自定义许可证，基于 RAIL，有使用限制条款）；DeepEvolve、SwarmEvolve、autoresearch（GitHub 上没有 license）。
  • 还不能用：SwarmEvolve 代码没发布（README 写着 “code coming soon”），而且它要自己托管模型才能共享 KV cache，本来就不能接 Bedrock。
  • 路线不同：Agent Lightning v1.0、ThetaEvolve 是用 RL 改模型权重，要 GPU，没法用 Bedrock 上托管的模型。Weco CLI 的搜索跑在 Weco 自己的服务器上，要账号和 credits。

2. Bedrock 接入要点（2026-11-24 实测）

  • 原生支持 Bedrock（代码里有 AnthropicBedrock 或 Bedrock 引擎）：ShinkaEvolve、DGM（模型 ID 是旧的）、AI Scientist（模型 ID 是旧的）、TextGrad（通过 langchain-aws）。HGM 的 requirements 里有 anthropic[bedrock]，没有实测。
  • 通过 LiteLLM 模型名接入（可以直接写 bedrock/...）：GEPA、DSPy（要装 dspy[litellm]）、LLM4AD、ReEvo、Trace、LEVI、EvoAgentX、Kayba ACE、AIRA-dojo。这些都是文档或代码里有这条路，都没有实测。
  • 只支持 OpenAI 兼容接口：OpenEvolve、SkyDiscover、CodeEvolve、EoH、GigaEvo、AHE、官方 ACE 等。有两种办法：
  • Claude 系列：Bedrock 的 OpenAI 兼容端点 https://bedrock-runtime.<region>.amazonaws.com/openai/v1/chat/completions 不支持 Claude。实测 Claude Opus 5.5（jp）、Sonnet 4.5、Haiku 4.5 都返回 404 model_not_found（"doesn't support this API"）。所以要在本机起一个 LiteLLM proxy（后端走 Bedrock Converse），再把 api_base 指向它。
  • 开源权重模型：同一个端点上 openai.gpt-oss-120b-1:0、openai.gpt-oss-20b-1:0、qwen.qwen3-coder-30b-a3b-v1:0、moonshot.kimi-k2-thinking 都能返回结果（us-east-1，SigV4）。用 OpenAI SDK 的话要用 Bedrock API key（bearer token）。好处是不用起 proxy，便宜，适合当 mutation 模型。
  • CLI 后端：OpenEvolve 有 provider: claude_code（另外还有 Codex、Copilot CLI）。Claude Code 本身可以走 Bedrock，所以理论上可以不起 proxy，但没有实测。

4. 逐个项目要点

4.1 程序 / 代码进化

ShinkaEvolve（基线）：SakanaAI/ShinkaEvolve，arXiv 2509.19349，ICLR 2026

  • 进化 EVOLVE-BLOCK 里的代码。用多个 island，父代采样时平衡探索和利用；新代码如果和旧的太像就丢掉（novelty 拒绝采样）；用 bandit 决定每次调哪个 LLM。
  • evaluate.py 里写 main(program_path, results_dir)，用 run_shinka_eval 跑，返回的 dict 里有 combined_score、public、private、text_feedback。
  • 原生支持 Bedrock：anthropic.AnthropicBedrock，认证用 Bedrock API key 或 AWS 凭证。可以本地并行跑，也可以上 Slurm。还有 WebUI，2026-02 起有给 Claude Code / Codex 用的 agent skills。
  • 结果：circle packing 只用约 150 个样本就到了新 SOTA；AIME harness；ALE-Bench；MoE 负载均衡 loss；帮一支队伍赢了 ICFP 2025 编程比赛。

OpenEvolve：algorithmicsuperintelligence/openevolve，没有自己的论文

  • MAP-Elites（同时追求分数高和种类多）+ island + 级联评估（先用便宜的测试筛一遍，再跑贵的）。可以加 LLM 当评委。
  • evaluate(program_path) 返回 dict 或 EvaluationResult(metrics={"combined_score": ...})，也可以写 evaluate_stage1/2 做级联。用 YAML 配置。
  • 后端：任何 OpenAI 兼容 API；另外有 Claude Code、Codex、Copilot CLI 三个 CLI provider（openevolve/llm/ 下面有 claude_code.py、codex_app_server.py、copilot_cli.py）。
  • 例子很多：circle packing、function minimization、TSP、symbolic regression、MLX Metal kernel、Rust 排序、prompt 优化、AlgoTune 等。自带 visualizer。
  • 很多后来的框架（SkyDiscover、ThetaEvolve、SwarmEvolve、CodeEvolve 的论文）都拿它当基线或者直接在它上面改。

SkyDiscover：skydiscover-ai/skydiscover，UC Berkeley Sky Lab，CAIS'26；AdaEvolve 2602.20133、EvoX 2602.23413

  • --search 可以选 adaevolve、evox、topk、beam_search、best_of_n、openevolve_native、gepa_native；外部后端 openevolve、gepa 用 uv sync --extra external 装，shinkaevolve 要手动装。
  • 评估器是 evaluate(program_path) 返回 dict，主目标是 combined_score，也可以做 Pareto 多目标。
  • README 说在 Frontier-CS 172 道题上，中位数比 OpenEvolve、GEPA、ShinkaEvolve 高约 34%（作者自己测的）。另外有 Synthesize 模式，让 coding agent 造一整套系统。
  • 风险：PyPI 上有个 skydiscover 0.1.0（2026-02），但没写项目链接，不能确认是同一个项目。核心用 OpenAI SDK，LiteLLM 只给 GEPA 后端用。

CodeEvolve：inter-co/science-codeevolve，arXiv 2510.14150，EMNLP 2026 Findings

  • island 遗传算法 + inspiration crossover + meta-prompting（连 prompt 一起进化），可选 MAP-Elites。只支持 OpenAI 兼容接口。
  • 评估器签名是 evaluate(code_path, results_path)，结果写成 JSON 文件。要求 Python ≥ 3.13.5，用 conda 装。所有实验数据都放在 HF dataset 上。
  • 注意：PyPI 上的 codeevolve 是别人的项目（ehallford11714/codeevolve）。

LLM4AD：Optima-CityU/LLM4AD，arXiv 2412.17287

  • 一个平台里有很多方法：EoH、FunSearch、ReEvo、HSEvo、MCTS-AHD、MEoH、NSGA2/MOEAD、LLaMEA、hill-climb 等，还有 GUI。
  • LLM 层有 LiteLLM 封装（注释里写了 bedrock/...），也支持 OpenAI、Ollama、vLLM 和多家国产云。
  • 接口是函数级的：写一个 Evaluation 类，实现 evaluate_program(program_str, callable_func)。不用 EVOLVE-BLOCK。

EoH / ReEvo / LLaMEA：三篇经典的“LLM 设计启发式”论文代码（ICML 2024 / NeurIPS 2024 / IEEE TEVC）。都偏组合优化或连续优化，接口是为特定问题定制的。EoH 团队现在推荐用 LLM4AD。

LEVI：ttanv/levi，arXiv 2605.09764

  • levi.evolve_code(..., score_fn, model, budget_dollars)，可以直接设美元预算。quickstart 约 0.05–0.10 美元。
  • README 说在 ADRS 7 道题上平均 76.5，高于 GEPA 71.9、OpenEvolve 70.6、ShinkaEvolve 67.4（作者自己测的）。只有 51 星。

GigaEvo（AIRI）：MAP-Elites + island + prompt 共进化，用 OpenAI 兼容接口，基础运行不需要 Redis。 ThetaEvolve：在 OpenEvolve 上加了 RL 训练，要 GPU 和 Docker。 SwarmEvolve：arXiv 2611.08483，Brown 大学。代码还没发布；思路是用 Qwen3 8B–32B 在单 GPU 上组成 swarm，共享 KV cache。 FunSearch / OpenELM / DeepEvolve / OpenAlpha_Evolve / EvoControl：见第 1 节“避开”。

4.2 会改自己代码的 agent

  • DGM（2505.22954）：agent 改自己的 Python 代码，改出来的版本都存进 archive，以后从里面选父代再改。默认的 coding 模型是 Bedrock 上的 Claude 3.5 Sonnet v2（dgm/llm_withtools.py）。论文附录 B.1 说一次 SWE-bench 运行约 2.2 万美元、约 2 周。
  • HGM（2510.21614，ICLR 2026 Oral）：在 DGM 代码上改。用 CMP（一个分支的子孙后来表现多好）来估计哪个节点值得扩展，再用 Thompson sampling 选。默认模型是 gpt-5-mini，max_workers 是 20。
  • Meta-Harness（2603.28052）：proposer 是 Claude Code，它通过文件系统读所有历史候选的代码、分数和 trace。有交互网页 demo。官方说明里列了 Claude Code skill 版（Harness Forge）和 Codex 版（SuperagenticAI/metaharness）。
  • AHE（2604.25850）：Terminal-Bench 2 上 69.7%→77.0%（GPT-5.4，10 轮），GPT-5.5 版 84.7%。依赖 E2B 沙箱和 Serper 搜索。
  • ADAS / AFlow / Gödel Agent / SICA：2024–2025 年的代表作，代码量小，方便读，但基本只支持 OpenAI，而且多数已经不更新了。
  • AIDE ML / Weco：AIDE 是开源的树搜索 ML agent；Weco CLI 是商业服务的客户端。
  • AI Scientist v1/v2：原生支持 Bedrock（旧模型 ID），要 GPU，许可证有限制条款（比如用它写的论文要显著声明是 AI 生成的）。
  • AIRA-dojo：CC BY-NC 4.0，不能商用。
  • Agent Lightning v1.0：用 RL 训练模型（verl + vLLM），要 Python ≥ 3.12 和 GPU。在 v1.0 的代码树里找不到早期的 APO（自动 prompt 优化）。

4.3 Prompt / 上下文 / 技能

  • GEPA（2507.19457）：读执行 trace，用自然语言反思，再改 prompt；用 Pareto 前沿保留各有长处的候选，再合并。论文：比 GRPO 平均高 10%，rollout 最多少 35 倍；比 MIPROv2 高 10% 以上。optimize_anything 能优化代码、配置、SVG 等。
  • DSPy（MIPROv2 论文 2406.11695）：生态最大，有 39k 星。新版默认用原生 lm15 引擎，provider 列表里没有 Bedrock，所以 Bedrock 要装 dspy[litellm]。
  • ACE（2510.04618）：上下文当作 playbook 来进化，agent 任务 +10.6%，金融任务 +8.6%。官方代码支持的 provider 少；Kayba 的 ace-framework 走 LiteLLM，更容易接 Bedrock。
  • TextGrad：原生有 Bedrock 引擎（langchain_aws.ChatBedrock）。Trace/OptoPrime：用装饰器标记哪段代码可以优化，默认走 LiteLLM。
  • EvoPrompt / PromptBreeder：早期的经典工作。DeepMind 的 PromptBreeder 没有官方代码，只有社区实现。

5. 客户常问，可以这样答

  • “有没有比 Shinka 更火的？” → OpenEvolve 星数最多（约 7.9k），接口和 Shinka 几乎一样，我们的 workshop 里有一节换引擎实验可以直接对比。
  • “Google 有 AlphaEvolve on Cloud，AWS 呢？” → AWS 上可以用开源引擎（Shinka / OpenEvolve）+ Bedrock + EC2 自己搭。Shinka 原生支持 Bedrock。生产场景下，AgentCore 有 optimization 功能（recommendations、A/B test），Bedrock 有 Prompt Optimization（见第 6 节 demo）。
  • “能改 agent 本身吗？” → 能。DGM / HGM 改 agent 的代码，Meta-Harness / AHE 改 harness，GEPA / ACE 改 prompt 和上下文。前两类成本高，适合拿来讲；后两类便宜，可以在课上做。
  • “要不要 GPU？” → 程序进化（Shinka / OpenEvolve / GEPA）只要 CPU 加 LLM API。只有 RL 路线（Agent Lightning、ThetaEvolve）和 autoresearch、AI Scientist 才要 GPU。

6. 行业知名 demo

说明：数字都来自原始博客、论文或 README，抓取日期 2026-11-24。写着“未核实”的，是没找到一手来源。

AlphaEvolve（Google DeepMind）

  • 讲什么：Gemini 写代码，自动打分，再进化，找到了新算法，而且已经用在 Google 的生产系统里。
  • 关键数字：
  • 4x4 复数矩阵乘法只用 48 次标量乘法，比 1969 年的 Strassen 方法更好。
  • Borg 调度启发式：平均回收 Google 全球 0.7% 的算力，已经上线 1 年以上。
  • Gemini 里一个矩阵乘法 kernel 提速 23%，Gemini 训练时间少了 1%。
  • FlashAttention kernel 最高提速 32.5%。
  • 50 多个数学开放问题：约 75% 追平已知最优解，约 20% 超过（比如 11 维 kissing number）。
  • 链接：https://deepmind.google/discover/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/ ，https://github.com/google-deepmind/alphaevolve_results ，https://github.com/google-deepmind/alphaevolve_repository_of_problems
  • 能不能便宜地重跑：不能。原系统不开源。alphaevolve_results 里的 Colab notebook 只能用来验证结果（免费，不要 GPU）。
  • Bedrock：不能（只用 Gemini）。
  • 适不适合 2–3 小时 workshop：部分适合。适合开场讲“为什么这件事重要”，但没法动手重跑。
  • 备注：DeepMind 博客发布于 2025-05-14；repo 里没有运行 AlphaEvolve 的代码。

AlphaEvolve on Google Cloud（托管服务 + Codelab）

  • 讲什么：同一个 AlphaEvolve 做成了云服务。Codelab 用 EVOLVE-BLOCK 标记，进化 26 圆 circle packing 和 TSP，评估在本地跑。
  • 关键数字：
  • 2025-12-09 私有预览，2026-07-09/10 GA。
  • Codelab 1 预计 45–60 分钟，评估在本地跑，不要 GPU。
  • 客户案例（Google 博客自己说的）：Coolblue 跑 200 次迭代，28 天需求预测的 WMAPE 改善 5% 以上；BASF 的规划/预测模型改善 80% 以上。
  • 另外还有两个 Codelab：在 Cloud Run 上进化编译型代码，在 GKE 上进化 LoRA 微调的超参数。
  • 链接：https://cloud.google.com/blog/products/ai-machine-learning/alphaevolve-is-available-for-everyone ，https://codelabs.developers.google.com/alphaevolve-on-google-cloud-1 ，https://codelabs.developers.google.com/alphaevolve-on-google-cloud-2 ，https://codelabs.developers.google.com/alphaevolve-on-google-cloud-3 ，https://github.com/Google-Cloud-AI/alphaevolve-on-googlecloud
  • 能不能便宜地重跑：要有 GCP 项目和 Gemini Enterprise app。费用 = AlphaEvolve API + Vertex Gemini token（具体单价未核实）。
  • Bedrock：不能（只在 GCP 上）。
  • 适不适合 2–3 小时 workshop：部分适合，可以当竞品参照。它的 Codelab 结构（seed 程序 + EVOLVE-BLOCK + 打分函数，先 circle packing 再 TSP）和我们的 workshop 几乎一样，客户很可能会拿来比。
  • 备注：客户问“Google 有托管的 AlphaEvolve，AWS 有吗”时，要准备好答案。

FunSearch（DeepMind，Nature 2023）

  • 讲什么：LLM 只改一个 priority 函数，就进化出了新的数学构造和更好的装箱启发式。
  • 关键数字：
  • n=8 维 cap set 大小 512（140 次实验里只有 4 次找到）。DeepMind 说这是 20 年来 cap set 下界最大的一次提升。
  • 在线一维 bin packing：进化出的启发式比 best-fit 等常用方法好。
  • 链接：https://deepmind.google/discover/blog/funsearch-making-new-discoveries-in-mathematical-sciences-using-large-language-models/ ，https://www.nature.com/articles/s41586-023-06924-6 ，https://github.com/google-deepmind/funsearch
  • 能不能便宜地重跑：Colab notebook 可以免费跑，能复核已经发现的函数，也能跑 bin packing 评估。implementation/ 目录只有单线程的骨架，不带 LLM 和沙箱，要自己接。
  • Bedrock：可以自己接（没有内置后端），要自己写 LLM 调用的代码。
  • 适不适合 2–3 小时 workshop：部分适合。bin packing 的评估很适合当“打分函数”的教学例子；完整重跑 cap set 太贵。
  • 备注：repo 最后一次 push 是 2024-02。

Karpathy autoresearch（2026-03）

  • 讲什么：coding agent（Claude 或 Codex）整夜自己改 train.py，每次训练 5 分钟，val_bpb 变好就保留这个改动。
  • 关键数字：
  • 约 2 天里试了约 700 个改动，找到约 20 个有用的。
  • 这些改动叠加以后，nanochat 的 Time-to-GPT-2 从 2.02 小时降到 1.80 小时（约 11%）。
  • 大约每小时 12 次实验，一夜约 100 次。
  • 链接：https://github.com/karpathy/autoresearch ，https://x.com/karpathy/status/2031135152349524125 ，https://github.com/karpathy/nanochat/commit/f06860494848db080c9a80a0ffa83203b042056b
  • 能不能便宜地重跑：要 1 张 NVIDIA GPU（作者用 H100 测的），每次 5 分钟。在 AWS 上用哪种 GPU 实例、多少钱，未核实。
  • Bedrock：可以。agent 就是 Claude Code，Claude Code 可以走 Bedrock。
  • 适不适合 2–3 小时 workshop：部分适合。它最有名（GitHub 约 10 万星），适合开场讲“大家都认识的例子”。但 2–3 小时只能跑十几次实验，而且要 GPU。
  • 备注：repo 没有 license（GitHub API 返回 license=null）。

Darwin Gödel Machine（DGM）

  • 讲什么：coding agent 改自己的代码，所有版本存成一棵进化树，在编程基准上越来越强。
  • 关键数字：
  • SWE-bench 20.0% → 50.0%。
  • Polyglot 全集 14.2% → 30.7%。
  • 一次 SWE-bench 运行约 2 周、约 2.2 万美元。
  • 链接：https://arxiv.org/abs/2505.22954 ，https://github.com/jennyzzt/dgm
  • 能不能便宜地重跑：很贵。完整跑 SWE-bench 约 2.2 万美元。论文附录估计，用 o3-mini 在 Polyglot 60 道题上做一次评估约 5 美元。要 Docker。
  • Bedrock：代码里有（dgm/llm.py 用 anthropic.AnthropicBedrock，默认是旧的 Claude 3.5 Sonnet v2 模型 ID）。README 只写了 OpenAI 和 Anthropic 的 key。整套在 Bedrock 上跑没有实测。
  • 适不适合 2–3 小时 workshop：动手不适合，讲故事适合。结果图很有说服力，但没法在课上重跑。
  • 备注：README 有警告：会执行模型生成的、不可信的代码。

Sakana The AI Scientist v1 / v2

  • 讲什么：从想法、做实验、写论文到审稿，全部自动完成。
  • 关键数字：
  • v1：每篇论文约 15 美元。
  • v2：3 篇论文投到 ICLR 2025 workshop，其中 1 篇平均分 6.33（约前 45%），超过平均录用线。按事先的约定，在正式发表前撤回了。
  • v2 实验阶段用 Claude 3.5 Sonnet 每次约 15–20 美元，写论文再加约 5 美元。

  • 能不能便宜地重跑：要 Linux + NVIDIA GPU（CUDA/PyTorch），每次几十美元。
  • Bedrock：原生支持（README 里有 “Claude Models via Bedrock”）。
  • 适不适合 2–3 小时 workshop：部分适合。能用 Bedrock 跑，但要 GPU，一次要几个小时。适合拿一个已经跑完的结果来演示。

OpenEvolve circle packing（n=26）

  • 讲什么：开源复现 AlphaEvolve 的 26 圆 circle packing。
  • 关键数字：

ShinkaEvolve 的四个 demo（Sakana，2025-09）

Voyager（Minecraft 技能库）

GEPA / DSPy 提示词优化教程

  • 讲什么：用反思来进化提示词（Pareto + 反思）。optimize_anything 还能优化代码、配置和 agent 结构。
  • 关键数字：
  • README 的快速例子：GPT-4.1 Mini 在 AIME 2025 上从 46.6% 提到 56.6%。

  • ARC-AGI agent：32% → 89%（靠架构发现）。
  • Databricks 博客说：开源模型 + GEPA 比 Claude Opus 4.1 便宜 90 倍。
  • 链接：https://github.com/gepa-ai/gepa ，https://dspy.ai/tutorials/gepa_aime/ ，https://dspy.ai/tutorials/gepa_ai_program/ ，https://gepa-ai.github.io/gepa/blog/introducing-optimize-anything/
  • 能不能便宜地重跑：很便宜。只调 LLM API，CPU 就够。DSPy 教程是 notebook（在 docs 里的 index.ipynb）。
  • Bedrock：通过 LiteLLM（DSPy 和 GEPA 的模型名可以写 bedrock/...），这次没有实测。
  • 适不适合 2–3 小时 workshop：适合。30–45 分钟能跑完一轮，成本低。也适合放在“换引擎”模块：从改代码换成改提示词。

Meta-Harness 交互式 demo（Stanford，2026-03）

  • 讲什么：让 Claude Code 当 proposer，读之前所有候选的源码、日志和分数，再进化 agent 的 harness。

7. 没能核实 / 要注意的

  • 下面这些 Bedrock 路径都只是“文档或代码里有”，没有实测：OpenEvolve + LiteLLM proxy、OpenEvolve 的 claude_code provider 走 Bedrock、GEPA / DSPy / LLM4AD / LEVI 用 bedrock/... 模型名、HGM、Meta-Harness。放进课程前要先端到端跑一遍。
