AlphaEvolve 详解

Google DeepMind 的「进化式写代码 agent」:它是什么、怎么工作、做成了什么、企业怎么用、局限在哪,以及和 RSI 的关系。整理于 2026-11-18。

一句话:AlphaEvolve 用 Gemini 不停地改一段代码,再用你写的打分程序给每个新版本打分,分高的留下来接着改 —— 像生物进化一样,一代代逼近更好的算法。它强在「能自动打分」的问题上,比如数学、芯片、调度、性能优化。
一手= DeepMind / Google 原文、论文、官方仓库。二手= 转述或未核实。判断= 这一页作者的看法。客户成绩都是客户和 Google 自己公布的。

① 它是什么

「AlphaEvolve 是一个由大语言模型驱动的进化式写代码 agent,用于通用的算法发现和优化。它把 Gemini 模型的创造力和验证答案的自动评测器结合起来,并用进化框架不断改进最有希望的想法。」

原文:「an evolutionary coding agent powered by large language models for general-purpose algorithm discovery and optimization. AlphaEvolve pairs the creative problem-solving capabilities of our Gemini models with automated evaluators that verify answers…」—— Google DeepMind,2025-05-14

  • 谁做的:Google DeepMind 的 AlphaEvolve 团队(白皮书作者包括 Alexander Novikov、Matej Balog、Pushmeet Kohli 等)。一手
  • 前身:2023 年的 FunSearch —— 第一次证明大模型能写出代码、在开放科学问题上发现可证明正确的新知识。FunSearch 只能进化单个函数;AlphaEvolve 能进化整个代码库,写出复杂得多的算法。一手
  • 适合什么问题:DeepMind 的原话是「进步能被清楚、系统地衡量的领域,比如数学和计算机科学」。也就是:能写一个程序,自动判断答案好不好。一手

② 它怎么工作

四个部件

  • Prompt sampler(提示词采样器):从程序库里挑一个「父程序」和几个「灵感」程序,拼成给模型的提示词。
  • LLMs ensemble(多个模型一起用):Gemini Flash 又快又便宜,负责广撒网,多出想法;Gemini Pro 更强,负责深挖,给出更有见地的改法。模型输出的是对代码的修改(diff),不是整段重写。
  • Evaluators pool(评测器):运行每个新程序并打分,可以有多个指标。评测可以分层:先跑便宜的检查,通过了才跑贵的完整评测(白皮书叫 evaluation cascade)。
  • Program database(程序库):存下所有程序和分数,用进化算法决定下一轮从哪些程序出发 —— 不只挑最好的,也保留多样性。

一轮循环(图中的伪代码)

父程序, 灵感 = 程序库.抽样()
提示词     = 提示词采样器.拼(父程序, 灵感)
修改       = 大模型.生成(提示词)
子程序     = 应用修改(父程序, 修改)
结果       = 评测器.运行(子程序)
程序库.加入(子程序, 结果)

你在代码里用 EVOLVE-BLOCK-START / EVOLVE-BLOCK-END 标出「允许改的部分」,其余部分(比如输入输出、评测接口)保持不变。Google 的 skill 优化教程就是把 SKILL.md 的文字放进这两个标记中间,让它改。一手

在 Google Cloud 上:生成在云上,评测在你那边

  • 生成这一半(提示词采样、Gemini 模型、程序库)是 Google Cloud 托管的。
  • 评测这一半由你自己跑,在你自己的机器或目标硬件上。官方原话:「AlphaEvolve 在 Google Cloud 里运行,不运行你的代码。它的反馈就是你的评测器送回来的分数和说明。」一手 · Google Cloud 博客
  • 所以评测的算力(以及评测写得好不好)是你的事 —— 大规模时可以用 Cloud Batch 把评测扇出到几百台机器。

③ 它做成了什么

Google 自己的系统

  • 数据中心调度:给 Borg 找到一个简单有效的调度启发式,已上线一年多,平均持续回收 Google 全球 0.7% 的算力。一手
  • Gemini 训练:把一个关键矩阵乘法 kernel 提速 23%,Gemini 训练时间减少 1% —— 包括训练 AlphaEvolve 自己用的模型。kernel 优化从「专家几周」变成「自动实验几天」。一手
  • GPU 底层:FlashAttention kernel 最高提速 32.5%。一手
  • 芯片:提出一个 Verilog 改写,去掉矩阵乘法电路里多余的位,通过严格验证后进入下一代 TPU。Jeff Dean:「TPU 的大脑在帮着设计下一代 TPU 的身体。」一手
  • 数据库和缓存:改进 Spanner 的 LSM 树压缩策略,写放大降低 20%;找到更好的缓存替换策略,两天做完以前要几个月人力的工作。一手 · 2026-05 一周年博客

数学

  • 4×4 复数矩阵乘法只要 48 次标量乘法,这是 1969 年 Strassen 算法以来,56 年里在这个设定下的第一次改进。一手
  • 在 50 多个开放问题(分析、几何、组合、数论)上:约 75% 追平已知最好结果,约 20% 刷新了已知最好结果。大部分实验几个小时就能搭好。一手
  • 和 Terence Tao 等人合写的论文测了 67 个问题,多数追平、若干刷新,有时还能从有限个例子归纳出对所有输入都成立的公式;并和 Deep Think、AlphaProof 组合做自动证明。一手 · arXiv 2511.02864
  • 2026-08:和 MIT、哥大、CMU 的学者一起,把矩阵乘法指数的上界从 ω < 2.371339 推进到 ω < 2.371177。一手 · arXiv 2608.16884

科学

  • 基因组:改进 DNA 测序纠错模型 DeepConsensus,变异检测错误减少 30%(PacBio 在用)。
  • 电网:最优潮流问题上,神经网络找到可行解的比例从 14% 提到 88% 以上。
  • 量子:给 Google Willow 量子芯片设计的量子电路,误差比传统优化低 10 倍。
  • 灾害预测:20 类自然灾害的综合预测准确率提高 5%。一手 · 2026-05 一周年博客

④ 企业怎么用

  • 时间线:2025-12 在 Google Cloud 开放私有预览;2026-07-09 正式商用(GA),所有 Google Cloud 客户都能用,入口在 Gemini Enterprise Agent Platform。一手
  • 官方四步:
    1. Define(定义):给种子算法、问题定义和背景知识。
    2. Measure(衡量):写打分函数,按正确性、性能、运行约束等一个或多个指标给候选打分。
    3. Optimize(优化):让 AlphaEvolve 针对这些指标生成优化后的代码。
    4. Apply(应用):把最终算法部署到生产。一手
  • 客户端库和示例:Google-Cloud-AI/alphaevolve-on-googlecloud(Apache 2.0),从「纯 Python 本地评测」到「在 GKE 上跑 GPU 训练」都有例子;最快的入门是填圆问题,约 5 分钟跑通。一手
  • 默认模型:2026-10-26 起新实验默认用 Gemini 4 Argon,按 Argon 的 token 价格计费。二手 · release notes 转载
  • 大规模评测:AlphaEvolve on Cloud Batch(SC26,2026-11-13),一个蓝图把几百个候选评测扇出到多台机器,支持多节点 MPI 和 Spot。一手

⑤ 局限和要注意的地方

  • 没有好的打分程序就用不了。它的效果上限取决于你的评测器。Tao 等人的论文也说:AlphaEvolve 不是「解所有数学问题的通用工具」,主要针对「构造一个满足数量性质的对象」这类问题。一手
  • 会钻评测的空子。Google 的视频处理教程举了例子:如果只看速度,进化循环可能干脆跳过渲染来「变快」,所以要加画质指标(SSIM)当门槛。一手
  • 进度不是平滑的。官方仓库提醒:最好分数可能卡很多代然后突然跳一下,「不要因为看起来卡住就提前停」;很多候选会失败,失败信息也会反馈给模型。一手
  • 评测的算力在你这边。生成是托管的,但每个候选都要在你的环境里跑一遍,大规模时这部分是主要成本 —— 和本场分享里「97.7% 的钱花在评测」是同一个道理。判断
  • 绑定 Gemini。托管版用 Gemini;官方开源的最小实现(见 ⑦)也是调 Gemini API。

⑥ 和 RSI 的关系

  • 它本身不算 RSI。在《The Last AI Built by Humans》的五级图里,AlphaEvolve 被放在 B0(只在一次任务里反复改答案)—— 因为它改的是你给的代码,改进的不是它自己(见 RSI 全景 图 5)。
  • 但它离 RSI 很近。DeepMind 原文写着:它让 Gemini 训练快了 1%,「包括训练 AlphaEvolve 自己所用的大模型」;它也在帮着设计下一代 TPU。也就是 用 AI 改进造 AI 的东西 —— 只是每一轮之间还是人在决定用不用、怎么用。一手 判断
  • 它是很多 RSI 研究的「引擎」:Google 用它改 agent 的 skill;开源的 ShinkaEvolve、OpenEvolve 被拿来改 harness、改训练代码。引擎是通用的,把改进的对象换成 AI 自己,并让改好的结果留到下一轮,才往 RSI 走。

⑦ 开源替代,以及在 AWS 上怎么做

  • 官方最小实现:google-deepmind/alphaevolve(2026-11-04 公开,Apache 2.0)。/src 是带本地评测的最小实现(需要 Docker 和 Gemini API key);/maths、/omega 是数学结果和验证用的 Colab。一手
  • OpenEvolve:algorithmicsuperintelligence/openevolve,自称「AlphaEvolve 的开源实现」,约 7.8k 星,可以接多家模型。
  • ShinkaEvolve:SakanaAI/ShinkaEvolve,Sakana AI 的版本,更省样本;本场 demo 用的就是它。
  • 在 AWS 上 判断:目前没有对标 AlphaEvolve 的托管服务。等价做法是 开源引擎(ShinkaEvolve / OpenEvolve)+ Bedrock 上的模型做生成 + AWS Batch / EC2 Spot 跑评测,结构和 Google 的「生成在云上、评测在你那边」一样。demo 里的「冻结权重,只改检索代码:0.42 → 0.94」就是这么跑的。
