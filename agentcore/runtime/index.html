AgentCore Runtime：microVM 还是 Instances

两种计算方式怎么选：对比、费用计算器、实测。

1 · 对比 2 · 费用 3 · 实测 4 · 上手
结论
  1. 默认用 microVM：启动快（几秒）、按用量付费、不用运维。
  2. 要 x86 / GPU、超过 8 小时、或者要 root（封网络、跑容器）才用 Instances。
  3. 用 Instances 一定要删会话：停会话不会关 EC2，而且这些实例默认在 EC2 列表里看不到。

高亮 结论 · 文档 出处见文末 · 实测 我在东京区域测的（2026-11-25）

要点本节关键信息

踩到的坑

  1. 停会话不关机器：要调 DeleteCapacityProviderSession，否则一直计费。
  2. 实例默认隐藏：查的时候加 --include-managed-resources。
  3. STANDARD 模式权限被收掉：不能切换用户、不能改 iptables，要用特权模式。
  4. 请求是分块传的（chunked，没有 Content-Length）。
  5. 特权模式要新版 SDK（boto3 ≥ 1.44.11）。

4 · 上手 Instances

# 1. 基础设施角色：信任 bedrock-agentcore.amazonaws.com，挂 BedrockAgentCoreRuntimeInstancesOperatorRolePolicy
# 2. capacity provider
aws bedrock-agentcore-control create-capacity-provider --name my_cp \
  --permissions-configuration capacityProviderOperatorRoleArn=<角色 ARN> \
  --compute-configuration '{"ec2Configuration": {
     "launchTemplateSource": {"launchParameters": {"operatingSystem": "LINUX_ARM64",
        "instanceRequirements": {"allowedInstanceTypes": ["m8g.large"]}}},
     "vpcConfiguration": {"subnets": ["<子网>"], "securityGroups": ["<安全组>"]}}}'
# 3. runtime 挂到 capacity provider 上
aws bedrock-agentcore-control create-agent-runtime --agent-runtime-name my_agent \
  --agent-runtime-artifact containerConfiguration={containerUri=<ECR 镜像>} --role-arn <执行角色 ARN> \
  --capacity-provider-configuration capacityProviderArn=<capacity provider ARN>
# 4. 用完：停，再删会话
aws bedrock-agentcore stop-runtime-session --agent-runtime-arn <runtime ARN> --runtime-session-id <会话 ID>
aws bedrock-agentcore delete-capacity-provider-session --capacity-provider-id <ID> --session-id <会话 ID>
