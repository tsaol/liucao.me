Amazon Bedrock AgentCore：跑 agent 的全套服务

agent 上线要的不只是调模型：在哪里跑、怎么隔离、怎么调工具、记住什么、用谁的身份、做得好不好。AgentCore 把这些拆成一个个托管服务。这页是总览，Runtime 单独有一页深入讲。

查阅日期 2026-11-25。服务名单、上限和价格以 AWS 官方文档为准；文中"实测"部分是我自己在东京区域（ap-northeast-1）测的。
先看这里：三句话
  1. AgentCore 是 AWS 上"跑 agent"的一整套托管服务。框架（Strands、LangGraph、CrewAI……）和模型（Bedrock 里的、外面的）都随你选，每个服务都能单独用。
  2. 核心是 Runtime：把你的 agent 放进容器，每个会话一个隔离的环境，按用量付费，空闲缩到 0。
  3. 其他服务围着它转：工具（Gateway、Code Interpreter、Browser）、记忆和身份（Memory、Identity）、治理（Policy、Registry）、质量（Observability、Evaluations、Optimization）。

1 · 它是什么

要点本节关键信息
  • 官方定义：用任何框架、任何基础模型，安全地、大规模地构建、部署和运行 agent，不用管基础设施。文档 · What is
  • 服务是模块化的：可以一起用，也可以只用其中一个，比如只用 Runtime 跑自己的 agent，或者只用 Gateway 把 API 变成 MCP 工具。文档 · What is

一个 agent 真正上线，除了"调模型"，还要一堆东西：在哪里跑、怎么隔离、怎么调用工具、记住什么、用谁的身份访问别的系统、怎么看它做了什么、做得好不好。AgentCore 把这些拆成一个个托管服务，你只写 agent 本身的逻辑。

官方给的三类典型用途：agent 应用（客服、流程自动化、数据分析、编程助手）、工具和 MCP 服务器（把现有 API、Lambda 包装成工具）、agent 平台（给公司内部开发者一条"铺好的路"）。文档 · What is

2 · 13 个服务，一张图

要点本节关键信息
  • 按用途分成五组：运行、工具、记忆与身份、治理、质量。文档 · What is
  • 第一次用最快的入口是 Harness：一次 API 调用就能定义并运行一个 agent（模型、提示词、工具直接写在请求里）。文档 · What is

运行

Runtime托管的 agent 运行环境，每个会话隔离；有 microVM 和 Instances 两种计算方式（见下一页）。
Harness托管的 agent 循环：编排、调工具、记忆都由它管；每个会话一台 microVM，带文件系统和 shell。

工具

Gateway把 API、Lambda、现有服务变成 MCP 工具，也能接已有的 MCP 服务器。
Code Interpreter隔离的沙箱，给 agent 跑 Python / JavaScript / TypeScript。
Browser托管的云端浏览器，让 agent 填表、点网页、抓信息。
Web Search / Web Answer2026-11 新增的托管工具（不在官方 13 个服务之内）：一次调用搜网页，或直接拿到带出处的回答。

记忆与身份

Memory短期记忆（多轮对话）和长期记忆（跨会话），可以在多个 agent 之间共享。
Identityagent 的身份和授权，对接 Cognito、Okta、Entra ID 等现有身份系统。

治理

Policy确定性的规则：在每次工具调用前拦下来检查，规则可以用自然语言或 Cedar 兼容的策略语言写。
Registry公司内部的 agent、MCP 服务器、工具、skill 目录，带审核和发布流程。
Payments让 agent 付小额费用调用收费 API（x402、MPP 协议），可以设花费上限。

质量

Observability每一步的轨迹、日志、指标（OpenTelemetry），在 CloudWatch 里看。
Evaluations自动评测 agent 完成任务的质量，内置评估器或自定义。
Optimization根据轨迹生成改进建议（提示词、工具描述），再用 A/B 测试验证。

3 · 从哪里开始

要点本节关键信息
  • 只想快速试一个 agent：用 Harness，不用写容器。文档 · What is
  • 已经有自己的 agent 代码（任何框架）：打成容器放进 Runtime，实现两个接口就行：GET /ping 和 POST /invocations，端口 8080。文档 · Instances 入门
  • Harness：模型、系统提示词、工具都写在一次调用里；适合原型、内部小工具。
  • Runtime：自己的框架和依赖、自己的容器镜像；适合正式上线、要控制环境的场景。
  • 按需加别的服务：要调公司 API 就加 Gateway；要记住用户就加 Memory；要管住 agent 能做什么就加 Policy；上线后用 Observability 和 Evaluations 盯质量。

4 · 最近的更新（2026 下半年）

要点本节关键信息
  • 新一代 Runtime 从 11-12 起是默认（东京在内）：会话从快照启动，2 GB 镜像 P75 不到 2 秒。What’s New 11-12
  • Runtime instances（8-06 正式发布）让 agent 跑在你自己账号里的 EC2 上，之后陆续加了特权模式、嵌套虚拟化和 G7 GPU。What’s New
08-06Runtime instances 正式发布：在自己账号的 EC2 上跑 agent，会话最长 14 天。
09-18新一代 Runtime（V2）发布：内存按需分配、用完回收，冷启动稳定在约 2 秒。
11-05Web Answer：返回带出处的综合答案的托管工具。
11-10Web Search API：一次调用搜索网页。
11-12V2 成为新建 runtime 的默认版本；会话最大 8 vCPU / 32 GB，镜像最大 10 GB。
11-16Runtime instances 新增 6 个区域。
11-18Runtime instances 支持特权模式：agent 可以装系统软件、跑嵌套容器。
11-19Runtime instances 支持嵌套虚拟化（KVM，Intel 机型）；Harness 增加 Strands 默认配置、内置工具和生命周期钩子。
11-20Runtime instances 支持 G7 GPU 实例。
