EC2 三层监控体系

CloudWatch → CloudWatch Agent → Prometheus + Node Exporter。搭配三大方法论：USE / RED / Four Golden Signals。

1 · 方法论——USE / RED / Golden Signals

方法视角三个指标适合看
USE
(Brendan Gregg)		 资源，自下而上 Utilization / Saturation / Errors host、每个资源（CPU / mem / disk / net / mutex / FD limit）[1]
Four Golden Signals
(Google SRE)		 请求，自上而下 Latency / Traffic / Errors / Saturation 面向用户的服务，做告警[2]
RED
(Tom Wilkie)		 请求，简化版 Rate / Errors / Duration 无状态 HTTP 服务

三者不冲突：在 EC2 上，host 层 USE（Node Exporter）+ 应用层 Golden Signals（自定义 exporter / OpenTelemetry）配合就够了。Gregg 的原话："solves about 80% of server issues with 5% of the effort."[1]

Google SRE Book 关于 Latency 特别提醒：成功请求的延迟要和错误请求的延迟分开算。"a slow error is even worse than a fast error"——一个慢慢返回的 500 比快速失败糟糕得多。[2]

2 · 三层数据源，越往下越准越贵

层能看到看不到成本
1 · CloudWatch built-in CPU、NetworkIn/Out、DiskReadBytes、StatusCheckFailed 内存、文件系统占用、进程列表、TCP 连接状态——因为是从 hypervisor 采 Basic 免费，Detailed ~$2.10/月/instance
2 · CloudWatch Agent 层 1 + 内存 + 磁盘用量 + statsd + 日志 协议层（TCP RTT、retransmit） ~$0.30/metric/月 + 日志
3 · Prometheus + Node Exporter 全量 /proc / /sys——1000+ 指标 协议层要再上 tcpstat / eBPF exporter EC2 + 存储；无 metric 计价，长期最便宜

证明层 1 不够——跑一次这个 API：

aws cloudwatch list-metrics \
  --namespace AWS/EC2 \
  --dimensions Name=InstanceId,Value=<你的实例ID>

返回里有 CPUUtilization、NetworkIn/Out、DiskReadBytes、StatusCheckFailed、EBSReadOps。没有 MemoryUsed、DiskSpaceUsed_Percent、ProcessCount、TCPEstablished。这些指标必须来自 guest 里的 agent。

3 · CloudWatch Agent——AL2023 + Graviton

安装命令 x86 和 arm64 一样，包会自动装对架构：

sudo dnf install -y amazon-cloudwatch-agent
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
  -a fetch-config -m ec2 -s \
  -c file:/opt/aws/amazon-cloudwatch-agent/etc/cwa-config.json

典型 Flask / Gunicorn 服务的 cwa-config.json：

{
  "agent": { "metrics_collection_interval": 60, "run_as_user": "cwagent" },
  "metrics": {
    "namespace": "MyApp/EC2",
    "append_dimensions": {
      "InstanceId": "${aws:InstanceId}",
      "AutoScalingGroupName": "${aws:AutoScalingGroupName}"
    },
    "metrics_collected": {
      "mem":     { "measurement": ["mem_used_percent", "mem_available"] },
      "disk":    {
        "measurement": ["used_percent", "inodes_free"],
        "resources": ["/", "/var/log"],
        "ignore_file_system_types": ["sysfs", "devtmpfs", "tmpfs"]
      },
      "netstat": { "measurement": ["tcp_established", "tcp_time_wait"] },
      "swap":    { "measurement": ["swap_used_percent"] }
    }
  },
  "logs": {
    "logs_collected": { "files": { "collect_list": [
      { "file_path": "/var/log/gunicorn/access.log",
        "log_group_name": "/myapp/gunicorn/access",
        "log_stream_name": "{instance_id}",
        "retention_in_days": 14 }
    ]}}
  }
}

IAM：给实例 role 加 CloudWatchAgentServerPolicy managed policy。

4 · Node Exporter（AL2023 · arm64）

VERSION=1.8.2
curl -sL https://github.com/prometheus/node_exporter/releases/download/v${VERSION}/node_exporter-${VERSION}.linux-arm64.tar.gz \
  | sudo tar -xz -C /usr/local/bin --strip-components=1 \
    node_exporter-${VERSION}.linux-arm64/node_exporter
sudo useradd -rs /sbin/nologin node_exporter

Systemd unit：

[Unit]
Description=Node Exporter
After=network.target

[Service]
User=node_exporter
Group=node_exporter
ExecStart=/usr/local/bin/node_exporter \
  --collector.systemd \
  --collector.processes \
  --collector.textfile.directory=/var/lib/node_exporter/textfile
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

默认关闭但值得开的 collectors [4]

  • --collector.systemd——unit 状态（哪些 service failed）。
  • --collector.processes——聚合 /proc 计数（Grafana dashboard 1860 需要）。
  • --collector.textfile——写自定义指标进 *.prom 文件（cron 结果、backup exit code）。写入用 mv 保证原子性。
  • 按需：logind、ethtool、interrupts、mountstats（NFS）。
README 明确警告："Enable at most one at a time, testing first"——每加一个 collector 都要看 scrape_duration_seconds 有没有变差。[4]

日常必备指标

  • node_load1——1 分钟 load average
  • node_memory_MemAvailable_bytes——kernel 承诺可回收的量
  • node_filesystem_avail_bytes{mountpoint="/"}——真实可用磁盘
  • node_disk_io_time_seconds_total——IO 时间累计
  • node_cpu_seconds_total{mode="iowait"}——"为啥慢"最好的入口

Node Exporter 看不到的：TCP RTT / retransmit / SACK（用 ss -ti 或 eBPF tcplife）；per-process CPU/RSS/FD（用 process_exporter）；HTTP 探针（blackbox_exporter）。

5 · Prometheus 最小配置

global:
  scrape_interval: 30s
  evaluation_interval: 30s

scrape_configs:
  - job_name: node
    ec2_sd_configs:
      - region: ap-northeast-1
        port: 9100
    relabel_configs:
      - source_labels: [__meta_ec2_tag_Name]
        target_label: instance

remote_write:
  - url: https://aps-workspaces.ap-northeast-1.amazonaws.com/workspaces/ws-xxx/api/v1/remote_write
    sigv4: { region: ap-northeast-1 }

本地保留：--storage.tsdb.retention.time=15d。长保留 remote_write 到 Amazon Managed Prometheus（默认 150 天，可延长）。

AMP + AMG vs Grafana Cloud 定价

  • AMP：$0.90 / 10M ingest（前 2B）、$0.10 / 1B query samples、$0.03 / GB 存储。Free tier：40M ingest + 10 GB。[5]
  • Amazon Managed Grafana：$9 / editor、$5 / viewer / 月，Enterprise 插件 +$45。每个 workspace 至少一个 editor。[6]
  • Grafana Cloud free tier：10k active series + 50 GB logs + 14 天保留——单台机器的小项目最省。

Grafana Dashboard ID 速查

  • 1860 — Node Exporter Full（经典）
  • 12486 — Node Exporter Full Modernized（新 Prometheus）
  • 7362 — MySQL Overview（需 mysqld_exporter）
  • 763 — Redis（需 redis_exporter）

7 · Alertmanager 生产级路由

route:
  receiver: default-slack
  group_by: [alertname, cluster]
  group_wait: 30s
  routes:
    - matchers: [team="db", severity="critical"]
      receiver: db-pagerduty
    - matchers: [team="frontend"]
      receiver: frontend-slack
      continue: true

receivers:
  - name: db-pagerduty
    pagerduty_configs:
      - routing_key: <key>
        send_resolved: true
  - name: frontend-slack
    slack_configs:
      - channel: '#fe-alerts'
        send_resolved: true

inhibit_rules:
  - source_matchers: [severity="critical"]
    target_matchers: [severity="warning"]
    equal: [alertname, cluster]

用 amtool check-config 验证；子路由继承父级未设的字段。inhibit 规则在 critical 已经触发时抑制同名 warning，避免"一次故障刷屏"。

四条起手告警规则

groups:
  - name: ec2.rules
    rules:
      - alert: HighCPU
        expr: 100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
        for: 5m
        labels: { severity: warning }

      - alert: LowMemory
        expr: node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes * 100 < 10
        for: 3m
        labels: { severity: critical }

      - alert: HighIOWait
        expr: avg by (instance) (rate(node_cpu_seconds_total{mode="iowait"}[5m])) * 100 > 30
        for: 5m
        labels: { severity: warning }

      - alert: InstanceStatusCheckFailed
        expr: aws_ec2_status_check_failed > 0
        for: 2m
        labels: { severity: critical }

8 · 3 台机器的 最小闭环

别造监控平台。做这 5 件事：

  1. 3 台机器都装 Node Exporter（10 分钟搞完）
  2. 注册 grafana.com 免费账号（10k active metrics、50 GB logs、14 天保留）
  3. 用 grafana-agent 或 remote_write 推到免费端点
  4. Import dashboard 1860
  5. 配四条告警：CPU>80%、mem<10%、disk<15%、EC2 status check failed

这就是全部。分布式 tracing、自定义 dashboard、日志聚合，第一天都不用做。
