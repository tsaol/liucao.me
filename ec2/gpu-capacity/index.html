按需抢 GPU：ODCR + 自动重试

GPU 紧张的时候，开机器总是报 InsufficientInstanceCapacity。这篇讲怎么用按需容量预留（ODCR）把空出来的 GPU 容量先占住，再慢慢用。附一个开源脚本，抢到为止。

1 · 为什么用 ODCR 2 · 脚本怎么抢 3 · 怎么用 4 · 抢之前检查 5 · 欧洲 GPU 分布 6 · 费用和释放
一句话版
  1. 别用 run-instances 抢：机器一关，容量就还回去了。
  2. 用 ODCR 抢：只要机型 + AZ + 数量，抢到就一直是你的，开关机都不丢。
  3. 多机型、多 AZ、减半重试、越等越久，碰到配额错误马上停。
  4. ODCR 生效就按按需价收费，不用了一定要释放。

1 · 为什么用 ODCR，不直接 run-instances

两种方式都是按需价格，碰到没货也都会报 InsufficientInstanceCapacity，所以都要重试。区别在于抢到以后能不能留住。

run-instances（直接开机器）ODCR（按需容量预留）
拿到的是什么一台运行中的机器某个 AZ、某个机型的容量，给你留着
每次重试要准备AMI、子网、安全组、密钥、磁盘只要机型、AZ、数量
stop / terminate 以后容量还回去，下次可能开不出来容量还是你的
只抢到一部分MinCount 可以少拿一次请求要么全给要么不给，所以要减半重试
价格按需价，机器运行时收按需价，生效就收，用不用都收
Savings Plans能用能用
适合马上就要跑任务先抢住，再配环境、交付使用
结论：抢 GPU 用 ODCR。容量拿到手以后，机器开、关、换镜像都不会丢；要给谁用，再在这个容量里开机器就行。

2 · 脚本怎么抢

脚本叫 grab-gpu.sh，只用 bash 和 AWS CLI。每一轮这样跑：

  1. 查哪些 AZ 有这个机型，没有的组合直接跳过，不浪费请求。
  2. 按你给的机型顺序，在每个 AZ 里申请剩下的全部数量。
  3. 没容量就减半再试：4 → 2 → 1。空出几台就先占几台。
  4. 抢到的预留都打上 tag，以后能查、能一键释放。可选：发 SNS 消息。
  5. 这一轮都失败，就等更久再来：30 秒起，每轮乘 1.5，最多 5 分钟，加随机抖动。抢到一次就重置。
  6. 碰到配额、权限、参数错误马上停：这些错误重试也没用。
# 退出码
0  全部抢到
2  选的机型在这些 AZ 都没有
3  致命错误（配额不够、没权限）
4  到了 --max-hours 还没抢满

3 · 怎么用

# 先测：--dry-run 只检查权限和参数，不创建
./grab-gpu.sh -r eu-central-1 -t g6e.12xlarge -n 2 --dry-run

# 抢 4 台：先 g6e.12xlarge，再 g6e.24xlarge，抢到发 SNS
./grab-gpu.sh -r eu-central-1 -t g6e.12xlarge,g6e.24xlarge -n 4 \
  -s arn:aws:sns:<region>:<account>:<topic>

# 放后台一直跑
nohup ./grab-gpu.sh -r eu-central-1 -t p4d.24xlarge -n 2 > grab.out 2>&1 &

./grab-gpu.sh -r eu-central-1 --status    # 看抢到了什么
./grab-gpu.sh -r eu-central-1 --release   # 全部释放，停止收费

抢到以后怎么开机器

默认是 open 模式：同一个账号里，机型、平台、AZ 对得上的机器会自动用这个预留，正常 run-instances 就行。如果只想给指定的机器用，加 --targeted，开机时再指定预留 ID。

4 · 抢之前检查

  • 先查按需 vCPU 配额（Running On-Demand G and VT / P instances）。很多时候失败不是没货，是配额不够。一台 p4d.24xlarge 就是 96 vCPU；ODCR 也算在配额里。
  • 机型和 AZ 多给几个。业务能接受的话，把 g6e、g7 这类同级别的都写上，选择越多越容易抢到。
  • 先跑 --dry-run，确认权限（创建、查询、取消预留，打 tag，可选 SNS）。
  • 量大或长期要用，同时找 AWS account team。脚本只能抢偶尔空出来的容量。

6 · 费用和释放

  • ODCR 一生效就按按需价收费，没开机器也收；开了机器不会重复收。
  • Savings Plans 的折扣对 ODCR 也有效。
  • 脚本建的预留没有结束时间，随时可以取消：./grab-gpu.sh --release。
  • 多个任务一起跑时，用 --tag 分开，释放时不会互相影响。
