P0 45 seconds Page just opened · Explain the topic with three cards
Look at the three cards at the top of the page:What gets improved is an e-commerce search agent · Method is having AI rewrite, generation after generation, its search() Code · Engine It uses Sakana AI's open-source ShinkaEvolve. The one on the left 30% is the starting point · the middle 3 generations is the number of iterations · the right side tells you the proposer is Claude via Bedrock.
Point to the three cards in order:E-commerce Search Agent(blue) → Have AI rewrite code(purple) → ShinkaEvolve(green) · blue, purple, and green plus the arrows between them form the visual through-line of "input → method → engine".
Don't click Start yet · first make sure the audience understands "what I'm about to show them".

P1 10 seconds Click Start · Set the pace
Now I'll click Start. The whole process runs over 3 generations · I'll pause between each one · so everyone can see a generation's verdict before deciding whether to run the next.
In the control bar, press ▶ Start · Or just press Space · The timer on the right will start running.
The audience will see what's moving right away · don't talk over it.
P2 15 seconds Run Gen 0 · Run a BM25 baseline
The first node lights up:Run parent code · collect trajectories. Generation 0 has no parent · the system just runs the BM25 baseline · to get a starting score.
Workflow step 1 node pulses green · the subtitle reads "Gen 0 is special · archive is empty · run the BM25 baseline directly".
This step isn't exciting · cover it in one sentence · the audience is already looking down at Verify.
P3 40 seconds Verify Gen 0 · Per-question scoring · card currently being scored
Now the main act makes its first appearance · Watch Currently scoring This big card: each time a cell lights up, the card switches to that question. The top shows the tier label, the original query, and the expected answer · if the answer is wrong, the actual answer is shown too. This is the evaluation system's Transparency: it doesn't just hand you a score of 30 and call it done · it lets you see for yourself where it went wrong.
Point to two places:Currently scoring Large card (above the grid) · and The i icon next to NDCG(hover to explain what each metric means). These two spots are where the audience most easily gets lost · the presenter should actively guide their attention.

P4 25 seconds Verify Commit Gen 0 · Missed-question review table + overall score
All 31 questions done · results appear below automatically Missed-question review table — 18 misses · by tier: E 1 · M 3 · H 14. This isn't decoration · this is The list of wrong answers the next-generation AI will learn from: what the query is, what's expected, what actually came back — the AI uses this table to make targeted code changes. Next, look at node 5: composite score 0.420 · Greater than 0 · Gen 0 baseline archived.
Point out two things:Missed-question review The "18/31 · E 1 · M 3 · H 14" summary line next to the title · and Commit in the node NDCG 30.2% + Blended score 0.420.
Hover over Blended score i icon next to it · shows the formula 0.7·public + 0.2·hold-out + 0.1·typo − 0.005·code penalty · Explain that "the overall score isn't just the main score · there's also an anti-cheating layer".
Blended score: four weighted terms (this is the formula behind the i icon on the page)
Public×0.7 hold-out×0.2 · anti-memorization typo×0.1 · anti-lookup Code penalty−0.005
An eval system doesn't give you 1 score · it gives you 3 layers of anti-cheating.
P5 15 seconds Gate 1 · Whether to enter Gen 1
Below the workflow appears a Bottom tip card —— Lists Gen 0's six scores: NDCG@5 30.2% · Tier E/M/H · Hold-out 60% · composite score 0.420. This card doesn't cover the page — I can keep scrolling, hover over tooltips, chat a bit — it just waits for me.
When you're ready to continue · press Enter or just click▶ Next generation. You can drop in a Q&A too — the card won't disappear.
I control the pace · the page doesn't play it for me.
P6 30 seconds Observe Gen 1 · How parents are selected · Weight bar visualization
Gen 1 starts · enters the second node first Select parent + view its report card. Look at this part: the archive has only one candidate, Gen 0, for now · but below it appears How it was selected panel — use softmax(score / 0.15) Turns scores into sampling probabilities · higher scores are more likely to be picked · but never exclusively. This logic gets more interesting after 4-5 real generations · for now it just makes the "hidden logic explicit" so you can take a look.
Point to Archive(only 1 slot) · then point to How it was selected weighted sampling bars in it · the green 100% bar = Gen 0 selected this round.
Now look below — Problems the parent got wrong The panel appears · it's a condensed version of the 18 missed questions from the previous segment · Tier H first · sorted by NDCG, low to high.This is the strongest evidence for evaluation-first: Before the AI writes any code · the system has already packaged up the problems it needs to solve and handed them to it.
Evals first · not process decoration · they're what you feed the AI Structured input.
P7 75 seconds Propose Gen 1 · AI's reasoning + code diff
On to the third node · blocks pop up one by one on the right side of the page — first🧠 AI's reasoning: Claude Opus 4.8 gave three points · Wrong language(BM25 can't match mixed Chinese-English text) · Scored 0 on every intent/semantic question(Tier H) · Negation and attributes not handled. Then it gives the plan a name:llm_reranker_full_catalog —— since the catalog is only 30-40 SKUs · just stuff the whole thing into the LLM and let it rerank. This Chinese reasoning is generated live by the model · not a script I hardcoded.
The two streaming panels should be read together:AI's reasoning(purple border · typewriter effect) · below is AI-proposed changes(diff view · red for deletions, green for additions · also streams in line by line). Wait until both panels have filled before moving on to the section below.
Look at the diff: it's not adding a line to tweak parameters · it's Full rewrite —— 500+ lines of code Changed the retrieval strategy. BM25 is demoted from primary ranking to fallback · the main path goes through the LLM. This is the essential difference between harness evolution and fine-tuning — what changes is Code · not Weights.
Gen 1 · llm_reranker_full_catalog

Can't change its own brain · so it changes the code it works with.
P8 40 seconds Verify Commit Gen 1 · All green, full marks · 30 to 91
Node 4 · score each task and run again. This time, watch the cell colors. The Tier H row was almost entirely red before · now All green. All 31 questions hit · Tier H jumps from 2% to 85% · hold-out jumps from 0.60 to 1.0.The hold-out is 5 problems the AI never sees —— it went up · so it's not memorizing answers · it's real generalization.
Point to the two "scarce pieces of evidence":Tier H · 15/15 hits(the H row goes from all red to all green) · and Hold-out 100%. Don't just praise the 91.2% — the hold-out score is the punch.

P9 10 seconds Gate 2 · Run another generation?
The bottom tip card appears a second time.Here's a chance to build some suspense —— ask the audience: "Since Gen 1 is already at 91% · do we still need to run Gen 2?" Pause two seconds before pressing continue.
Press Enter or click ▶ Next generation.

P10 60 seconds Propose Commit Gen 2 · CoT attempts · diminishing returns
Gen 2 · this time the AI proposes calling it enable_cot_reasoning · Have the LLM, before answering, first Short reasoning · added FINAL: separator. Its motivation: Gen 1 is already decent · the remaining weak spots are concentrated in the most implicit-intent questions (Reading on a kindle late at night and wanting some ambiance → Retro ambient lamp) · makes the model think one more step.
Look at node 5: NDCG is still 91.2% · but the overall score 0.936 → 0.929 —— dropped. Tier H rose from 85 to 89 · but Tier M dropped from 94 to 87. This is Diminishing returns: The model has a ceiling · 3 generations of evolution captured everything available.
Compare the two generations' gen cards (stacked at the bottom in order): Gen 1 "Overall 0.936" · Gen 2 "Overall 0.929". Gen 2's Tier H 89% is a new high · but Tier M dropped—— this is what a real run looks like · not a monotone increase.

Evolution doesn't always go up — the gate decides what to accept and what to roll back · the Gate is in charge.
P11 75 seconds Wrap-up · Eval is the asset
Three generations done · three Gen cards stacked at the bottom · further down is Method references: ACE · Meta-Harness · DGM · ShinkaEvolve · each one is a clickable arxiv link. You've now seen the whole path — but what's really scarce Not these papers · not the Claude weights either · it's those 31 + 5 + 31 questions. Models change every quarter · Opus will be outdated next year too · but your eval system · no one can take that from you.
Scroll all the way down to the Method references · All 4 pills are clickable — when the audience asks about a paper, just click it · no need to switch to the browser.
Models go stale · harnesses evolve · but Evals are the only asset that lasts.
📋 Rehearsal notes When the page changes · what the presenter needs to keep in sync
  1. Data sources: All numbers come from static/harness/play-run.json(Gen 0 baseline · Gen 1 llm_reranker_full_catalog · Gen 2 enable_cot_reasoning). If you switch to new run results, the numbers must be recomputed — especially the tables in P3 / P4 / P8 / P10.
  2. Default speed 0.25×: scoring 31 queries ≈ 12 s · reasoning typewriter ≈ 25 s · diff streaming in ≈ 10 s. About 60 s per generation · 3-4 min for three generations. If that's too slow · in the JS console speed=1 can be accelerated.
  3. Gate pause: After each generation finishes · a "Next generation" card appears at the bottom · press Enter to continue · the page won't advance on its own. The card doesn't cover the page · the presenter can scroll while talking.
  4. i icon: NDCG · composite score · Hold-out · Tier · all have tooltips. If presenting on mobile, remember to tap them (tap = .show) · on desktop, just hover.
  5. Local backup(presenter notes · not presented on stage):/static/harness/play-standalone.html is the same content · single file · double-click to open. deploy.sh rebuilds it automatically. Just download it to a USB drive or your desktop before going on stage.
