04
Two lanes · θ slow loop and Σ fast loop
covers slides 18–20
The whole field summed up in one formula:Aₜ₊₁ = IMPROVE(A₁:ₜ ; Sₜ). An agent consists of weights θ and scaffold Σ · which one you change determines the loop'sPace and risk. 2026 consensus: Σ first, then θ —— Σ explores and validates first; stable strategies are then distilled into θ.
θSlow parameter loop · Change weights
Self-distillation · self-rewarding RL · RLVR · TTT: capabilities truly internalized
  • Endogenously generated demonstrations Dₜ · endogenous evaluation eₜ · exogenous trajectories τₜ
  • High cost · risk of catastrophic forgetting
  • Typical examples: SPICE · Self-play SWE-RL · AAR
Slow · costly · irreversible
ΣScaffold fast loop · edit code
prompt · memory · tools · full scaffold — transparent and reversible
  • Prompt · Memory · Tools · Full Scaffold (self-modifying code)
  • Low latency · risk of structural drift
  • Typical examples: DGM · Meta-Harness · AHE · ShinkaEvolve
Fast · Cheap · Reversible
The experiments + demo in this talk only touch the Σ side · not a single model parameter is changed
🔁 Terminology patch · What is RSI Recursive Self-Improvement
RSI = AI improves itself generation after generation · then uses the improved version to keep improving.Recursive(recursive) = the output is fed back in as input;Self(self) = it modifies itself, not something else;Improvement(improvement) = theoretically better each round. This is the shared mathematical backbone of every method in this talk (DGM · AlphaEvolve · ShinkaEvolve).
Aₜ₊₁ = IMPROVE(A₁:ₜ ; Sₜ)
A = agent config (θ Weights + Σ scaffold) · S = improvement signal (demonstrations / evaluations / exploration experience)
3 tiers · Each builds on the last
Bounded self-refinementRunnable today
EvaluatorFixed, what gets improvedFixed · Converges, auditable · already industrialized.
🎯 The demo you're watching is at this level.
Semi-openResearch frontier
Improvement operators are partly mutable · but the evaluation criteria stay fixed.
Typical examples:DGM · HGM · Mendel-GM · AHE
Open-ended RSIControlled experiment
Improvement mechanism and Even the evaluation criteria evolve · constrained by grounding / collapse / compute.
This is the core worry in AGI discussions.
Bounded RSI → Semi-open → Open-ended RSI → AGI → ASI
2026 engineering consensus: Get the left side right first (bounded) · leave the right side for controlled experiments (verbatim from PPT slide 18)
  • Bounded self-refinement — Fixed evaluator, fixed improvement target · already industrialized today
  • Open-ended RSI — The improvement mechanism and evaluation criteria evolve too · constrained by grounding, collapse, and compute
  • Engineering consensus — Mainstream 2026 systems: "Get the left side (bounded) right first, leave the right side to controlled experiments"

07
Evaluation philosophy · Delta Attribution
covers slides 25–26
The score gains don't come for free. Every point breaks down into three parts — T is borrowed (extra compute) · O is rented (eval shortcuts) · G is earned (real improvement). Only G is a transferable, shippable gain.
T · Borrowed
O · Rented
G · Earned
T · Extra compute: disappears once the baseline is budget-matched
O · Benchmark shortcut: falls apart outside that benchmark
G · Earned: still improves across models/datasets
How the Harvey experiments map: cost penalty → controls T · leakage audit → controls O · cross-model transfer → validates G
  • MLS-Bench's three constraints — Gains must be attributable, hold across ≥3 evaluation settings, and preserve ranking at scale
  • Corresponding design in the Live Demo — Blended score breakdown barMake T/O/G explicit (public quiz / hold-out / robustness / code penalty)
  • The line that hurts the most — "Whether the improvement mechanism can be trusted is harder than whether the score went up"

L4Becoming routineNightly automation · CI gate · production A/B
← Bottom up, layer by layer · each layer's output is the next layer's input
  • Five implementation challenges — Observability · evaluation · generalization · cost · ceiling
