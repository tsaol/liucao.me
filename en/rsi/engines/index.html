Open-source self-evolving engines and industry demos

Survey for hands-on agent self-evolution / RSI labs: besides ShinkaEvolve, which open-source frameworks exist, what each one modifies, how to connect them to Amazon Bedrock, and whether they fit a 2–3 hour workshop; plus the well-known industry demos. Data comes from each project's GitHub, PyPI, README, papers and official blogs, checked on 2026-11-24. Where marked "unverified" or "not tested", defer to the original sources.

Related:RSI talk · Case study: Xiaohongshu × AWS AI Lab Research Agent · AlphaEvolve Explained · Paper Explainers
  • Date: 2026-11-24 (GitHub stars, license, and last push were all fetched that day via the GitHub REST API)
  • Main engine: ShinkaEvolve (baseline)
  • Method: GitHub API, PyPI JSON, shallow-cloning 40 repos and grepping them (bedrock / litellm / anthropic / openai), reading READMEs and docs, and checking paper titles with the HF papers API. We tested Bedrock's OpenAI-compatible endpoint (see Section 2).
  • Raw data:engines.json(each project's fields, plus demos)
  • “Not tested” means the path exists in the docs or code, but we haven't actually run it.

1. Conclusions (start here)

Engine-swap module, 1–2 recommended:

  1. OpenEvolve(first choice): 7,861 stars, Apache-2.0, still had pushes on 2026-11-24.
  2. The evaluator interface is almost the same as ours:evaluate(program_path) Returns a dict containing combined_score, and the evolve block also uses EVOLVE-BLOCK-START/END marker. Our score(program_path) Works with a one-line wrapper.
  3. pip install openevolve, with light dependencies and CPU only.
  4. Its approach differs from Shinka's (MAP-Elites + islands), so comparing them on the same problem works well.
  5. Downside: no native Bedrock support, only OpenAI-compatible APIs. To use Claude you first need to run a LiteLLM proxy (see Section 2).
  6. GEPA(second option, which changes "what gets evolved"): 7,560 stars, MIT.
  7. Switch from “modifying code” to “modifying prompts / skills / configs”.optimize_anything(seed, evaluator, objective) It can also wrap our score(program_path) inside it.
  8. Model names use LiteLLM format, so you can just write bedrock/..., with no proxy needed (not tested).
  9. Already integrated into DSPy (dspy.GEPA), which gives you a natural way to continue when customers ask about DSPy.
  10. Alternative: SkyDiscover(UC Berkeley, 769 stars, Apache-2.0). In a single CLI command, use --search lets you switch between adaevolve / evox / openevolve / gepa / shinkaevolve, while the evaluator is still evaluate(program_path) plus combined_score. It's the best fit for engine swapping, but its PyPI status is unclear. The README only says git clone + uv sync, and Bedrock also has to go through a proxy. Instructors should run it end to end themselves first, then decide whether to include it in the course.

Worth mentioning, but don't run it in class:

  • CodeEvolve, LLM4AD (a unified platform for EoH/FunSearch/ReEvo, etc.), LEVI, DSPy MIPROv2, TextGrad, Trace, ACE (Kayba version), Meta-Harness, AHE, DGM, HGM, ADAS, AFlow, AIDE, SICA, EvoAgentX, karpathy/autoresearch. The reasons vary: too heavy (Docker, SWE-bench, E2B), too expensive (one full DGM run costs about $22,000), an interface that's too different (DSPy requires rewriting the task as a program), or a project that's too new or too small.

Avoid:

  • Inactive: OpenELM (last push 2023-11), FunSearch reference code (2024-02, no LLM or sandbox), OpenAlpha_Evolve (2025-05), PromptBreeder community implementation (2024-08).
  • License issues: Meta AIRA-dojo (CC BY-NC 4.0, no commercial use); Sakana AI Scientist (custom license based on RAIL, with use-restriction clauses); DeepEvolve, SwarmEvolve, autoresearch (no license on GitHub).
  • Not usable yet: SwarmEvolve's code hasn't been released (the README says “code coming soon”), and it needs self-hosted models to share the KV cache, so it couldn't work with Bedrock anyway.
  • Different approach: Agent Lightning v1.0 and ThetaEvolve use RL to update model weights, which requires GPUs and can't use models hosted on Bedrock. Weco CLI's search runs on Weco's own servers and requires an account and credits.

2. Bedrock integration notes (tested 2026-11-24)

  • Native Bedrock support(the code has AnthropicBedrock or Bedrock engine): ShinkaEvolve, DGM (old model IDs), AI Scientist (old model IDs), TextGrad (via langchain-aws). HGM's requirements include anthropic[bedrock], not tested.
  • Connected via LiteLLM model name(you can write bedrock/...): GEPA, DSPy (requires installing dspy[litellm]), LLM4AD, ReEvo, Trace, LEVI, EvoAgentX, Kayba ACE, AIRA-dojo. Their docs or code all support this path,None tested.
  • OpenAI-compatible APIs only: OpenEvolve, SkyDiscover, CodeEvolve, EoH, GigaEvo, AHE, the official ACE, etc. There are two options:
  • Claude models: Bedrock's OpenAI-compatible endpoint https://bedrock-runtime.<region>.amazonaws.com/openai/v1/chat/completions No Claude support. In our tests, Claude Opus 5.5 (jp), Sonnet 4.5, and Haiku 4.5 all returned 404 model_not_found("doesn't support this API"). So you need to run a local LiteLLM proxy(backed by Bedrock Converse), then api_base point to it.
  • Open-weight models: on the same endpoint openai.gpt-oss-120b-1:0, openai.gpt-oss-20b-1:0, qwen.qwen3-coder-30b-a3b-v1:0, moonshot.kimi-k2-thinking All return results (us-east-1, SigV4). With the OpenAI SDK you need a Bedrock API key (bearer token). Upside: no proxy needed, it's cheap, and it works well as the mutation model.
  • CLI backend: OpenEvolve has provider: claude_code(plus Codex and Copilot CLI). Claude Code can use Bedrock directly, so in theory you don't need a proxy,but not tested.

4. Project-by-project notes

4.1 Program / code evolution

ShinkaEvolve (baseline): SakanaAI/ShinkaEvolve, arXiv 2509.19349, ICLR 2026

  • Evolves the code inside the EVOLVE-BLOCK. It uses multiple islands and balances exploration and exploitation when sampling parents, discards new code that's too similar to existing code (novelty rejection sampling), and uses a bandit to decide which LLM to call each time.
  • evaluate.py write in main(program_path, results_dir), using run_shinka_eval runs it, and the returned dict contains combined_score, public, private, text_feedback.
  • Native Bedrock support:anthropic.AnthropicBedrock, with authentication via a Bedrock API key or AWS credentials. It can run in parallel locally or on Slurm. There's also a WebUI, and since 2026-02 there are agent skills for Claude Code / Codex.
  • Results: new SOTA on circle packing with only about 150 samples; AIME harness; ALE-Bench; MoE load-balancing loss; helped a team win the ICFP 2025 programming contest.

OpenEvolve: algorithmicsuperintelligence/openevolve, no paper of its own

  • MAP-Elites (aims for both high scores and diversity) + island + cascade evaluation (screen with cheap tests first, then run the expensive ones). An LLM can be added as a judge.
  • evaluate(program_path) Returns a dict or EvaluationResult(metrics={"combined_score": ...}), or you can write evaluate_stage1/2 for cascading. Configured with YAML.
  • Backends: any OpenAI-compatible API, plus three CLI providers: Claude Code, Codex, and Copilot CLI (openevolve/llm/ Below are claude_code.py, codex_app_server.py, copilot_cli.py).
  • Many examples: circle packing, function minimization, TSP, symbolic regression, MLX Metal kernels, Rust sorting, prompt optimization, AlgoTune, and more. Comes with a built-in visualizer.
  • Many later frameworks (the SkyDiscover, ThetaEvolve, SwarmEvolve, and CodeEvolve papers) use it as a baseline or build directly on top of it.

SkyDiscover: skydiscover-ai/skydiscover, UC Berkeley Sky Lab, CAIS'26; AdaEvolve 2602.20133, EvoX 2602.23413

  • --search Options are adaevolve, evox, topk, beam_search, best_of_n, openevolve_native, gepa_native; for the external backends openevolve and gepa, use uv sync --extra external installs; shinkaevolve must be installed manually.
  • The evaluator is evaluate(program_path) Returns a dict; the primary objective is combined_score, and can also do Pareto multi-objective optimization.
  • The README reports a median about 34% higher than OpenEvolve, GEPA, and ShinkaEvolve across 172 Frontier-CS problems (self-reported). It also has a Synthesize mode where a coding agent builds an entire system.
  • Risk: PyPI has a skydiscover 0.1.0 (2026-02), but no project link is given, so we can't confirm it's the same project. The core uses the OpenAI SDK; LiteLLM is only used by the GEPA backend.

CodeEvolve: inter-co/science-codeevolve, arXiv 2510.14150, EMNLP 2026 Findings

  • Island-based genetic algorithm + inspiration crossover + meta-prompting (the prompts evolve too), with optional MAP-Elites. Only supports OpenAI-compatible APIs.
  • The evaluator signature is evaluate(code_path, results_path), and results are written to JSON files. Requires Python ≥ 3.13.5, installed with conda. All experiment data is on an HF dataset.
  • Note: on PyPI, the codeevolve is someone else's project (ehallford11714/codeevolve).

LLM4AD: Optima-CityU/LLM4AD, arXiv 2412.17287

  • Many methods in one platform: EoH, FunSearch, ReEvo, HSEvo, MCTS-AHD, MEoH, NSGA2/MOEAD, LLaMEA, hill-climb, and more, plus a GUI.
  • The LLM layer has a LiteLLM wrapper (the comments say bedrock/...), and also supports OpenAI, Ollama, vLLM, and several Chinese cloud providers.
  • The interface is function-level: write an Evaluation class and implement evaluate_program(program_str, callable_func). No EVOLVE-BLOCK needed.

EoH / ReEvo / LLaMEA: Code for three classic "LLM-designed heuristics" papers (ICML 2024 / NeurIPS 2024 / IEEE TEVC). All focus on combinatorial or continuous optimization, with interfaces tailored to specific problems. The EoH team now recommends LLM4AD.

LEVI: ttanv/levi, arXiv 2605.09764

  • levi.evolve_code(..., score_fn, model, budget_dollars), and you can set a dollar budget directly. The quickstart costs about $0.05–0.10.
  • The README reports an average of 76.5 on 7 ADRS problems, above GEPA (71.9), OpenEvolve (70.6), and ShinkaEvolve (67.4) (self-reported). Only 51 stars.

GigaEvo(AIRI): MAP-Elites + islands + prompt co-evolution. Uses an OpenAI-compatible API; basic runs don't need Redis. ThetaEvolve: Adds RL training on top of OpenEvolve; requires a GPU and Docker. SwarmEvolve: arXiv 2611.08483, Brown University. Code not yet released; the idea is to run a swarm of Qwen3 8B–32B models on a single GPU with a shared KV cache. FunSearch / OpenELM / DeepEvolve / OpenAlpha_Evolve / EvoControl: See "Avoid" in Section 1.

4.2 Self-modifying agents

  • DGM(2505.22954): The agent edits its own Python code and stores every resulting version in an archive, then later picks parents from it to edit further. The default coding model is Claude 3.5 Sonnet v2 on Bedrock (dgm/llm_withtools.py). Appendix B.1 of the paper says one SWE-bench run costs about $22,000 and takes about 2 weeks.
  • HGM(2510.21614, ICLR 2026 Oral): Built on the DGM code. It uses CMP (how well a branch's descendants later perform) to estimate which node is worth expanding, then selects with Thompson sampling. The default model is gpt-5-mini, and max_workers is 20.
  • Meta-Harness(2603.28052): The proposer is Claude Code, which reads the code, scores and traces of all past candidates through the file system. Has an interactive web demo. The official docs list a Claude Code skill version (Harness Forge) and a Codex version (SuperagenticAI/metaharness).
  • AHE(2604.25850): 69.7%→77.0% on Terminal-Bench 2 (GPT-5.4, 10 rounds), and 84.7% with GPT-5.5. Depends on E2B sandboxes and Serper search.
  • ADAS / AFlow / Gödel Agent / SICA: representative work from 2024–2025. The codebases are small and easy to read, but they mostly support only OpenAI, and most are no longer maintained.
  • AIDE ML / Weco: AIDE is an open-source tree-search ML agent; Weco CLI is the client for a commercial service.
  • AI Scientist v1/v2: Native Bedrock support (old model IDs), requires a GPU, and the license has restrictive terms (e.g., papers written with it must prominently state that they are AI-generated).
  • AIRA-dojo: CC BY-NC 4.0, no commercial use.
  • Agent Lightning v1.0: Trains models with RL (verl + vLLM); requires Python ≥ 3.12 and a GPU. The earlier APO (automatic prompt optimization) can't be found in the v1.0 code tree.

4.3 Prompt / context / skills

  • GEPA(2507.19457): Reads execution traces, reflects in natural language, then revises the prompt. It keeps a Pareto front of candidates with different strengths, then merges them. Paper: 10% higher than GRPO on average with up to 35x fewer rollouts; over 10% higher than MIPROv2.optimize_anything Can optimize code, configs, SVGs, and more.
  • DSPy(MIPROv2 paper 2406.11695): Largest ecosystem, with 39k stars. The new version uses the native lm15 engine by default, and Bedrock isn't in its provider list, so for Bedrock you need to install dspy[litellm].
  • ACE(2510.04618): Evolves context as a playbook: +10.6% on agent tasks, +8.6% on finance tasks. The official code supports few providers; Kayba's ace-framework Goes through LiteLLM, which makes it easier to connect to Bedrock.
  • TextGrad: Has a native Bedrock engine (langchain_aws.ChatBedrock).Trace/OptoPrime: Uses decorators to mark which code can be optimized; uses LiteLLM by default.
  • EvoPrompt / PromptBreeder: Early classic work. DeepMind's PromptBreeder has no official code, only community implementations.

5. Common customer questions and suggested answers

  • “Is there anything more popular than Shinka?” → OpenEvolve has the most stars (about 7.9k), and its interface is almost the same as Shinka's. Our workshop has an engine-swap lab where you can compare them directly.
  • “Google has AlphaEvolve on Cloud. What about AWS?” → On AWS, you can build your own with an open-source engine (Shinka / OpenEvolve) + Bedrock + EC2. Shinka supports Bedrock natively. For production, AgentCore has optimization features (recommendations, A/B tests), and Bedrock has Prompt Optimization (see the demo in Section 6).
  • “Can it modify the agent itself?” → Yes. DGM / HGM modify the agent's code, Meta-Harness / AHE modify the harness, and GEPA / ACE modify prompts and context. The first two are expensive, so they're better for discussion. The last two are cheap and can be done in class.
  • “Do we need GPUs?” → Program evolution (Shinka / OpenEvolve / GEPA) only needs CPUs plus an LLM API. Only the RL approaches (Agent Lightning, ThetaEvolve), autoresearch, and AI Scientist need GPUs.

6. Well-known industry demos

Note: All numbers come from the original blog posts, papers, or READMEs, retrieved on 2026-11-24. Items marked “unverified” are those for which no primary source was found.

AlphaEvolve (Google DeepMind)

  • What it is: Gemini writes code, which is scored automatically and then evolved. It found new algorithms that are already used in Google's production systems.
  • Key numbers:
  • 4x4 complex matrix multiplication with only 48 scalar multiplications, beating Strassen's 1969 method.
  • Borg scheduling heuristic: recovers 0.7% of Google's worldwide compute on average and has been in production for over a year.
  • 23% speedup on a matrix multiplication kernel in Gemini, cutting Gemini training time by 1%.
  • Up to 32.5% speedup on the FlashAttention kernel.
  • 50+ open math problems: matched the best known solution in about 75% of cases and surpassed it in about 20% (e.g., the kissing number in 11 dimensions).
  • Link:https://deepmind.google/discover/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/ , https://github.com/google-deepmind/alphaevolve_results , https://github.com/google-deepmind/alphaevolve_repository_of_problems
  • Cheap to rerun? No. The original system is not open source. The Colab notebook in alphaevolve_results can only be used to verify results (free, no GPU needed).
  • Bedrock: No (Gemini only).
  • Fit for a 2–3 hour workshop: Partly. Good for the opener on "why this matters," but you can't rerun it hands-on.
  • Note: The DeepMind blog post was published on 2025-05-14. The repo contains no code for running AlphaEvolve.

AlphaEvolve on Google Cloud (managed service + Codelab)

  • What it is: The same AlphaEvolve offered as a cloud service. The Codelab uses EVOLVE-BLOCK markers to evolve 26-circle circle packing and TSP, with evaluation running locally.
  • Key numbers:
  • Private preview 2025-12-09, GA 2026-07-09/10.
  • Codelab 1 takes about 45–60 minutes. Evaluation runs locally and doesn't need a GPU.
  • Customer cases (as reported in Google's own blog): Coolblue ran 200 iterations and improved WMAPE for 28-day demand forecasting by more than 5%; BASF improved its planning/forecasting models by more than 80%.
  • There are also two Codelabs: evolving compiled code on Cloud Run, and evolving LoRA fine-tuning hyperparameters on GKE.
  • Link:https://cloud.google.com/blog/products/ai-machine-learning/alphaevolve-is-available-for-everyone , https://codelabs.developers.google.com/alphaevolve-on-google-cloud-1 , https://codelabs.developers.google.com/alphaevolve-on-google-cloud-2 , https://codelabs.developers.google.com/alphaevolve-on-google-cloud-3 , https://github.com/Google-Cloud-AI/alphaevolve-on-googlecloud
  • Cheap to rerun? Needs a GCP project and a Gemini Enterprise app. Cost = AlphaEvolve API + Vertex Gemini tokens (unit prices unverified).
  • Bedrock: No (GCP only).
  • Fit for a 2–3 hour workshop: Partly; useful as a competitor reference. Its Codelab structure (seed program + EVOLVE-BLOCK + scoring function, circle packing first, then TSP) is nearly identical to our workshop, so customers will likely compare the two.
  • Note: Have an answer ready for when customers ask, “Google has a managed AlphaEvolve. Does AWS?”

FunSearch (DeepMind, Nature 2023)

  • What it is: An LLM changes only a single priority function and evolves new mathematical constructions and better bin-packing heuristics.
  • Key numbers:
  • Cap set of size 512 in n=8 dimensions (found in only 4 of 140 runs). DeepMind says this is the largest improvement to the cap set lower bound in 20 years.
  • Online 1D bin packing: the evolved heuristics beat common methods such as best-fit.
  • Link:https://deepmind.google/discover/blog/funsearch-making-new-discoveries-in-mathematical-sciences-using-large-language-models/ , https://www.nature.com/articles/s41586-023-06924-6 , https://github.com/google-deepmind/funsearch
  • Cheap to rerun? The Colab notebook runs for free, can verify the discovered functions, and can run the bin packing evaluation. The implementation/ directory is only a single-threaded skeleton with no LLM or sandbox; you have to wire those up yourself.
  • Bedrock: You can wire it up yourself (there's no built-in backend); you have to write your own LLM-calling code.
  • Fit for a 2–3 hour workshop: Partly. The bin packing evaluator is a good teaching example of a "scoring function"; a full cap set rerun is too expensive.
  • Note: The repo's last push was in 2024-02.

Karpathy autoresearch (2026-03)

  • What it is: A coding agent (Claude or Codex) edits train.py on its own overnight, training for 5 minutes each time, and keeps a change if val_bpb improves.
  • Key numbers:
  • Tried about 700 changes in about 2 days and found about 20 useful ones.
  • With these changes combined, nanochat's Time-to-GPT-2 dropped from 2.02 hours to 1.80 hours (about 11%).
  • About 12 experiments per hour, roughly 100 overnight.
  • Link:https://github.com/karpathy/autoresearch , https://x.com/karpathy/status/2031135152349524125 , https://github.com/karpathy/nanochat/commit/f06860494848db080c9a80a0ffa83203b042056b
  • Cheap to rerun? Needs 1 NVIDIA GPU (the authors tested on an H100), 5 minutes per run. Which GPU instance to use on AWS and the cost are unverified.
  • Bedrock: Yes. The agent is Claude Code, and Claude Code can run through Bedrock.
  • Fit for a 2–3 hour workshop: Partly. It's the best known (about 100k GitHub stars), so it's good for an opener with "an example everyone knows." But 2–3 hours only allows a dozen or so experiments, and it needs GPUs.
  • Note: The repo has no license (the GitHub API returns license=null).

Darwin Gödel Machine (DGM)

  • What it is: A coding agent edits its own code, stores every version in an evolutionary tree, and keeps getting stronger on coding benchmarks.
  • Key numbers:
  • SWE-bench: 20.0% → 50.0%.
  • Full Polyglot: 14.2% → 30.7%.
  • One SWE-bench run takes about 2 weeks and costs about $22,000.
  • Link:https://arxiv.org/abs/2505.22954 , https://github.com/jennyzzt/dgm
  • Cheap to rerun? Very expensive. A full SWE-bench run costs about $22,000. The paper's appendix estimates one evaluation on 60 Polyglot tasks with o3-mini at about $5. Requires Docker.
  • Bedrock: Present in the code (dgm/llm.py uses anthropic.AnthropicBedrock, defaulting to the older Claude 3.5 Sonnet v2 model ID). The README only mentions OpenAI and Anthropic keys. Running the full setup on Bedrock hasn't been tested.
  • Fit for a 2–3 hour workshop: Not for hands-on, but good for storytelling. The result charts are convincing, but you can't rerun it in class.
  • Note: The README warns that it executes untrusted, model-generated code.

Sakana The AI Scientist v1 / v2

  • What it is: Fully automated, from ideas and experiments to paper writing and review.
  • Key numbers:
  • v1: about $15 per paper.
  • v2: 3 papers were submitted to an ICLR 2025 workshop, and one received an average score of 6.33 (roughly the top 45%), above the average acceptance threshold. As agreed in advance, it was withdrawn before publication.
  • v2: the experiment phase with Claude 3.5 Sonnet costs about $15–20 per run, plus about $5 for writing the paper.
  • Link:https://sakana.ai/ai-scientist/ , https://sakana.ai/ai-scientist-first-publication/ , https://github.com/SakanaAI/AI-Scientist , https://github.com/SakanaAI/AI-Scientist-v2
  • Cheap to rerun? Needs Linux + an NVIDIA GPU (CUDA/PyTorch), tens of dollars per run.
  • Bedrock: Supported natively (the README has “Claude Models via Bedrock”).
  • Fit for a 2–3 hour workshop: Partly. It can run on Bedrock, but it needs GPUs and each run takes several hours. Best to demo with a result from a completed run.
  • Note: GitHub shows the license as NOASSERTION (it's actually the custom AI Scientist Source Code License). Read the terms carefully before commercial use.

OpenEvolve circle packing (n=26)

  • What it is: An open-source reproduction of AlphaEvolve's 26-circle circle packing.
  • Key numbers:
  • Sum of radii 2.634, only 0.04% off the AlphaEvolve paper's 2.635. The README says later evolution went on to surpass the paper's result.
  • Uses a two-stage config with max_iterations 100 per stage; the README records 470 generations of evolution.
  • Link:https://github.com/algorithmicsuperintelligence/openevolve/tree/main/examples/circle_packing
  • Cheap to rerun? CPU only. Total cost depends on the model used; the exact dollar amount is unverified.
  • Bedrock: Through an OpenAI-compatible interface (e.g. LiteLLM proxy). The README also says Claude Code and Codex CLI are supported.
  • Fit for a 2–3 hour workshop: Yes. You can compare it directly with Shinka on the same problem, and it comes with a visualizer.

ShinkaEvolve's four demos (Sakana, 2025-09)

  • What it is: Program evolution with fewer samples (higher sample efficiency).
  • Key numbers:
  • Circle packing with 26 circles: a new SOTA using only 150 samples.
  • AIME agent scaffold: evolved over 75 generations into a three-stage structure.
  • ALE-Bench / AtCoder AHC015: score rose from 762,641 to 817,371 (the blog says this score would rank 2nd).
  • MoE training: discovered a new load-balancing loss.
  • Link:https://sakana.ai/shinka-evolve/ , https://github.com/SakanaAI/ShinkaEvolve , https://sakanaai.github.io/ShinkaEvolve/webui/
  • Cheap to rerun? Circle packing needs only a CPU. Cost depends on the model used (exact amount unverified).
  • Bedrock: Supported natively (the README's configuration section covers Anthropic / Bedrock).
  • Fit for a 2–3 hour workshop: Yes. This is our main engine. Circle packing is the best first hands-on experiment, and the WebUI shows the evolution tree in real time.

Voyager (Minecraft skill library)

  • What it is: A GPT-4 agent in Minecraft sets its own learning plan, writes its own skill code, stores it in a skill library, and keeps learning.
  • Key numbers:
  • Found 3.3× as many distinct items as before (63 in 160 prompt rounds).
  • The distance traveled is 2.3 times as long.
  • Faster tech-tree unlocks: wood 15.3x, stone 8.5x, iron 6.4x.
  • Link:https://voyager.minedojo.org/ , https://github.com/MineDojo/Voyager , https://arxiv.org/abs/2305.16291
  • Cheap to rerun? Needs a licensed copy of Minecraft, Fabric mods, Node.js, and a Microsoft/Azure login. The repo's last push was 2024-04.
  • Bedrock: No (the code uses openai_api_key; switching to Bedrock requires your own changes).
  • Fit for a 2–3 hour workshop: not for hands-on work, but good for concepts: “a skill library is a form of memory-based self-improvement.”

GEPA / DSPy prompt optimization tutorial

  • What it is: Evolves prompts through reflection (Pareto + reflection). optimize_anything can also optimize code, configs, and agent structure.
  • Key numbers:
  • Quick example from the README: GPT-4.1 Mini on AIME 2025 goes from 46.6% to 56.6%.
  • Needs far fewer evaluations than GRPO: 100–500, versus 5,000–25,000+ for GRPO.
  • ARC-AGI agent: 32% → 89% (through architecture discovery).
  • The Databricks blog says open-source models + GEPA are 90x cheaper than Claude Opus 4.1.
  • Link:https://github.com/gepa-ai/gepa , https://dspy.ai/tutorials/gepa_aime/ , https://dspy.ai/tutorials/gepa_ai_program/ , https://gepa-ai.github.io/gepa/blog/introducing-optimize-anything/
  • Cheap to rerun? Very cheap. It only calls LLM APIs, so a CPU is enough. The DSPy tutorial is a notebook (index.ipynb in the docs).
  • Bedrock: Through LiteLLM (model names in DSPy and GEPA can be written as bedrock/...); not tested this time.
  • Fit for a 2–3 hour workshop: Yes. One round takes 30–45 minutes and costs little. It also fits the "swap the engine" module: moving from editing code to editing prompts.
  • Note: GEPA is integrated into DSPy, MLflow, and Google ADK.

Meta-Harness interactive demo (Stanford, 2026-03)

  • What it is: Uses Claude Code as the proposer, which reads the source code, logs, and scores of all previous candidates and then evolves the agent's harness.
  • Key numbers:
  • Web demo: 19 hard tasks from TerminalBench-2, going from 28.5% for Terminus-KIRA to 46.5% by round 7.
  • Text classification: 7.7 points above the best context-management method, with 4× fewer context tokens.
  • 200 IMO-level problems: the same harness gained an average of +4.7 points across 5 unseen models.
  • Each step uses up to about 10 million tokens of diagnostic context.
  • Link:https://yoonholee.com/meta-harness/ , https://arxiv.org/abs/2603.28052 , https://github.com/stanford-iris-lab/meta-harness
  • Cheap to rerun? The web demo is free to browse. An actual rerun uses a lot of tokens (possibly millions per step); exact cost unverified.
  • Bedrock: Yes. The proposer is Claude Code (which can run through Bedrock); the model under test depends on the specific example.
  • Fit for a 2–3 hour workshop: Partly. The web demo is great for a 5-minute in-class showcase of "harness self-evolution"; a full rerun is too expensive.

Amazon Bedrock AgentCore optimization (recommendations / A/B test / insights)

  • What it is: Uses production traces and evaluation scores to automatically suggest changes to the system prompt and tool descriptions. It runs offline batch evaluation first, then online A/B tests, and finally ships the winning version.
  • Key numbers:
  • Preview 2026-04-30.
  • 2026-06-17: batch evaluations, recommendations, and A/B tests went GA (14 Regions); failure / intent / trajectory insights entered preview (13 Regions).
  • Table from the AWS blog (2026-09-16): AppWorld baseline 72.62%, GEPA 79.63%, MIPROv2 74.40%, AWS single-agent reflector 81.55%, sub-agent reflector 95.83%.
  • AgentCore Evaluations: preview 2025-12-02, GA 2026-03-31.
  • Link:https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-bedrock-agentcore-new-optimization-capabilities/ , https://aws.amazon.com/blogs/machine-learning/optimizing-agent-system-prompts-with-amazon-bedrock-agentcore/ , https://aws.amazon.com/blogs/machine-learning/introducing-agent-quality-optimization-in-agentcore-now-in-preview/ , https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/optimization.html
  • Cheap to rerun? You first need a deployed agent and its traces; billed by AgentCore usage (unit price unverified).

  • Fit for a 2–3 hour workshop: Good for the final session. It grounds "self-evolution" in AWS managed products and answers "how do you use this in production?"

Workshop recommendations

  • Spend the first 10 minutes talking without running anything: AlphaEvolve (48 multiplications, Borg 0.7%), DGM (20%→50%), autoresearch (700 changes, about 11%), then open the Meta-Harness web demo.
  • Main hands-on track: run circle packing with ShinkaEvolve (CPU only, native Bedrock). To add engine swapping, run the same problem with OpenEvolve and compare. To change what gets optimized, use GEPA/DSPy to optimize AIME prompts.
  • Wrap-up: cover Bedrock Advanced Prompt Optimization and AgentCore optimization, explaining “how to do self-improvement in production the AWS-managed way.” Also be ready to answer “Google has AlphaEvolve on Cloud. What does AWS have?”
