Why split the four topics into subpages

At first I put all these topics on one page, and it read like a 30-screen memo. If technical content isn't organized "one topic at a time," attention drifts.

After the split: each article stands alone, supports deep reading, and includes citations; the navigation bar is consistent; subpages are chained together with "Next stop" links, and you can also jump around as needed. Readers can pick what to read or read straight through.

Recommended reading order for the four articles:01 → 03 → 02 → 04. First build intuition for hardware differences (01); then learn to read the metrics (03); then set up monitoring (02); finally turn it into a playbook (04). On large instances you also need to understand the physical architecture; see further reading NUMA——it's not just a Graviton problem.
