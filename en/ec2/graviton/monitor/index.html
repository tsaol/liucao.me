Three-layer EC2Monitoring stack

CloudWatch → CloudWatch Agent → Prometheus + Node Exporter, paired with three methodologies: USE / RED / Four Golden Signals.

1 · Methodology——USE / RED / Golden Signals

MethodPerspectiveThree metricsGood for
USE
(Brendan Gregg)		 Resources, bottom-up Utilization / Saturation / Errors host, each resource (CPU / mem / disk / net / mutex / FD limit)[1]
Four Golden Signals
(Google SRE)		 Request, top-down Latency / Traffic / Errors / Saturation For user-facing services, alert on it[2]
RED
(Tom Wilkie)		 Request, simplified Rate / Errors / Duration Stateless HTTP services

The three don't conflict:On EC2, host-level USE (Node Exporter) plus application-level Golden Signals (custom exporter / OpenTelemetry) is enough. In Gregg's words: "solves about 80% of server issues with 5% of the effort."[1]

The Google SRE Book has a special warning about latency:Latency of successful requestsneeds to be paired withLatency of failed requestsCount them separately. "a slow error is even worse than a fast error": a 500 that returns slowly is much worse than a fast failure.[2]

2 · Three layersData sources: the further down, the more accurate and the more expensive

LayerCan seeNot visibleCost
1 · CloudWatch built-in CPU, NetworkIn/Out, DiskReadBytes, StatusCheckFailed Memory, filesystem usage, process list, TCP connection state——because it's collected from the hypervisor Basic is free, Detailed ~$2.10/month/instance
2 · CloudWatch Agent Layer 1 + memory + disk usage + statsd + logs Protocol layer (TCP RTT, retransmit) ~$0.30/metric/month + logs
3 · Prometheus + Node Exporter Full /proc / /sys——1000+ metrics Go further up to the protocol layer tcpstat / eBPF exporter EC2 + storage; no per-metric pricing, cheapest long-term

Proof layer 1 isn't enough— run this API once:

aws cloudwatch list-metrics \
  --namespace AWS/EC2 \
  --dimensions Name=InstanceId,Value=<your-instance-ID>

The response includes CPUUtilization, NetworkIn/Out, DiskReadBytes, StatusCheckFailed, and EBSReadOps.None MemoryUsed, DiskSpaceUsed_Percent, ProcessCount, TCPEstablished. These metrics must come from an agent inside the guest.

3 · CloudWatch Agent——AL2023 + Graviton

The install command is the same on x86 and arm64; the package automatically installs the right architecture:

sudo dnf install -y amazon-cloudwatch-agent
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
  -a fetch-config -m ec2 -s \
  -c file:/opt/aws/amazon-cloudwatch-agent/etc/cwa-config.json

A typical Flask / Gunicorn service's cwa-config.json:

{
  "agent": { "metrics_collection_interval": 60, "run_as_user": "cwagent" },
  "metrics": {
    "namespace": "MyApp/EC2",
    "append_dimensions": {
      "InstanceId": "${aws:InstanceId}",
      "AutoScalingGroupName": "${aws:AutoScalingGroupName}"
    },
    "metrics_collected": {
      "mem":     { "measurement": ["mem_used_percent", "mem_available"] },
      "disk":    {
        "measurement": ["used_percent", "inodes_free"],
        "resources": ["/", "/var/log"],
        "ignore_file_system_types": ["sysfs", "devtmpfs", "tmpfs"]
      },
      "netstat": { "measurement": ["tcp_established", "tcp_time_wait"] },
      "swap":    { "measurement": ["swap_used_percent"] }
    }
  },
  "logs": {
    "logs_collected": { "files": { "collect_list": [
      { "file_path": "/var/log/gunicorn/access.log",
        "log_group_name": "/myapp/gunicorn/access",
        "log_stream_name": "{instance_id}",
        "retention_in_days": 14 }
    ]}}
  }
}

IAM: add to the instance role CloudWatchAgentServerPolicy managed policy.

4 · Node Exporter(AL2023 · arm64)

VERSION=1.8.2
curl -sL https://github.com/prometheus/node_exporter/releases/download/v${VERSION}/node_exporter-${VERSION}.linux-arm64.tar.gz \
  | sudo tar -xz -C /usr/local/bin --strip-components=1 \
    node_exporter-${VERSION}.linux-arm64/node_exporter
sudo useradd -rs /sbin/nologin node_exporter

Systemd unit:

[Unit]
Description=Node Exporter
After=network.target

[Service]
User=node_exporter
Group=node_exporter
ExecStart=/usr/local/bin/node_exporter \
  --collector.systemd \
  --collector.processes \
  --collector.textfile.directory=/var/lib/node_exporter/textfile
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

Collectors that are off by default but worth enabling [4]

  • --collector.systemd——unit status (which services failed).
  • --collector.processes— aggregate /proc counts (required by Grafana dashboard 1860).
  • --collector.textfile——write custom metrics into *.prom files (cron results, backup exit code).For writes, use mv Guarantees atomicity.
  • On demand:logind, ethtool, interrupts, mountstats(NFS).
The README explicitly warns:"Enable at most one at a time, testing first" — every time you add a collector, you need to check scrape_duration_seconds has gotten worse.[4]

Everyday essential metrics

  • node_load1——1-minute load average
  • node_memory_MemAvailable_bytes——the amount the kernel promises it can reclaim
  • node_filesystem_avail_bytes{mountpoint="/"}— actual usable disk
  • node_disk_io_time_seconds_total——cumulative IO time
  • node_cpu_seconds_total{mode="iowait"}——the best entry point for "why is it slow"

What Node Exporter can't see:TCP RTT / retransmit / SACK (using ss -ti or eBPF tcplife); per-process CPU/RSS/FD (using process_exporter); HTTP probes (blackbox_exporter).

5 · Prometheus Minimum configuration

global:
  scrape_interval: 30s
  evaluation_interval: 30s

scrape_configs:
  - job_name: node
    ec2_sd_configs:
      - region: ap-northeast-1
        port: 9100
    relabel_configs:
      - source_labels: [__meta_ec2_tag_Name]
        target_label: instance

remote_write:
  - url: https://aps-workspaces.ap-northeast-1.amazonaws.com/workspaces/ws-xxx/api/v1/remote_write
    sigv4: { region: ap-northeast-1 }

Kept locally:--storage.tsdb.retention.time=15d. Long retention remote_write to Amazon Managed Prometheus(150 days by default, extendable).

AMP + AMG vs Grafana Cloud pricing

  • AMP:$0.90 / 10M ingest(first 2B), $0.10 / 1B query samples, $0.03 / GB storage. Free tier: 40M ingest + 10 GB.[5]
  • Amazon Managed Grafana:$9 / editor, $5 / viewer / month, Enterprise add-on +$45. Each workspace needs at least one editor.[6]
  • Grafana Cloud Free tier: 10k active series + 50 GB logs + 14-day retention — the cheapest option for small single-machine projects.

Grafana Dashboard ID quick reference

  • 1860 — Node Exporter Full (classic)
  • 12486 — Node Exporter Full Modernized (newer Prometheus)
  • 7362 — MySQL Overview (requires mysqld_exporter)
  • 763 — Redis (requires redis_exporter)

7 · Alertmanager Production-grade routing

route:
  receiver: default-slack
  group_by: [alertname, cluster]
  group_wait: 30s
  routes:
    - matchers: [team="db", severity="critical"]
      receiver: db-pagerduty
    - matchers: [team="frontend"]
      receiver: frontend-slack
      continue: true

receivers:
  - name: db-pagerduty
    pagerduty_configs:
      - routing_key: <key>
        send_resolved: true
  - name: frontend-slack
    slack_configs:
      - channel: '#fe-alerts'
        send_resolved: true

inhibit_rules:
  - source_matchers: [severity="critical"]
    target_matchers: [severity="warning"]
    equal: [alertname, cluster]

Use amtool check-config validation; child routes inherit any fields they don't set from the parent. Inhibit rules suppress same-named warnings once a critical has fired, to avoid "one failure flooding the channel".

Four starter alert rules

groups:
  - name: ec2.rules
    rules:
      - alert: HighCPU
        expr: 100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
        for: 5m
        labels: { severity: warning }

      - alert: LowMemory
        expr: node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes * 100 < 10
        for: 3m
        labels: { severity: critical }

      - alert: HighIOWait
        expr: avg by (instance) (rate(node_cpu_seconds_total{mode="iowait"}[5m])) * 100 > 30
        for: 5m
        labels: { severity: warning }

      - alert: InstanceStatusCheckFailed
        expr: aws_ec2_status_check_failed > 0
        for: 2m
        labels: { severity: critical }

8 · A 3-machine Minimal closed loop

Don't build a monitoring platform. Do these 5 things:

  1. Install Node Exporter on all 3 machines (done in 10 minutes)
  2. Sign up for a free grafana.com account (10k active metrics, 50 GB logs, 14-day retention)
  3. Use grafana-agent or remote_write Push to a free endpoint
  4. Import dashboard 1860
  5. Set up four alarms: CPU>80%, mem<10%, disk<15%, EC2 status check failed

That's it. Distributed tracing, custom dashboards, and log aggregation aren't needed on day one.
