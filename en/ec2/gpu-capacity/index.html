On-Demand Grab GPUs: ODCR + auto-retry

When GPUs are scarce, launching instances keeps failing with InsufficientInstanceCapacity. This post shows how to use On-Demand Capacity Reservations (ODCR) to lock in GPU capacity as soon as it frees up, then use it at your own pace. Includes an open-source script that keeps trying until it succeeds.

1 · Why ODCR 2 · How the script grabs capacity 3 · How to use it 4 · Pre-flight checks 5 · GPU availability in Europe 6 · Cost and release
TL;DR
  1. Don't use run-instances to grab capacity: once the instance stops, the capacity goes back.
  2. Grab with ODCR: just instance type + AZ + count. Once you get it, it stays yours, whether instances are stopped or started.
  3. Multiple instance types, multiple AZs, halve-and-retry, longer waits each time, and stop immediately on quota errors.
  4. ODCR is billed at On-Demand rates once active, so be sure to release them when you're done.

1 · Why ODCR instead of plain run-instances

Both use On-Demand pricing, and both return an error when there's no capacity InsufficientInstanceCapacity, so both need retries. The difference is Can you keep it once you have it?.

Bottom line:Use ODCR to grab GPUs. Once you have the capacity, starting, stopping, or changing the AMI won't lose it. Whoever needs it just launches instances in that capacity.

2 · How the script grabs capacity

The script is called grab-gpu.sh, using only bash and the AWS CLI. Each round works like this:

  1. Check which AZs offer this instance type, and unavailable combinations are skipped, so no requests are wasted.
  2. In the order of instance types you give, request in each AZ all of the remaining count.
  3. If there's no capacity,Halve and retry: 4 → 2 → 1. Grab as many as free up.
  4. The reservation you got Everything is tagged, so you can find them later and release them in one step. Optional: send an SNS message.
  5. If the whole round fails,wait longer Retry: start at 30 seconds, multiply by 1.5 each round, cap at 5 minutes, and add random jitter. Reset after each successful grab.
  6. On Stop immediately on quota, permission, or parameter errors: retrying won't help with these errors.
# Exit codes
0  All secured
2  None of the chosen instance types are available in these AZs
3  Fatal error (insufficient quota, missing permissions)
4  Reached --max-hours without securing all

3 · How to use it

# Test first: --dry-run only checks permissions and parameters, creates nothing
./grab-gpu.sh -r eu-central-1 -t g6e.12xlarge -n 2 --dry-run

# Grab 4: g6e.12xlarge first, then g6e.24xlarge; send SNS when secured
./grab-gpu.sh -r eu-central-1 -t g6e.12xlarge,g6e.24xlarge -n 4 \
  -s arn:aws:sns:<region>:<account>:<topic>

# Keep it running in the background
nohup ./grab-gpu.sh -r eu-central-1 -t p4d.24xlarge -n 2 > grab.out 2>&1 &

./grab-gpu.sh -r eu-central-1 --status    # See what you got
./grab-gpu.sh -r eu-central-1 --release   # Release everything to stop charges

How to launch instances once you have it

The default is open mode: instances in the same account with matching instance type, platform, and AZ will automatically use this reservation, a normal run-instances works. If you only want specific instances to use it, add --targeted, then specify the reservation ID when launching.

4 · Pre-flight checks

  • Check your On-Demand vCPU quota first(Running On-Demand G and VT / P instances). Often the failure isn't a lack of capacity but insufficient quota. A single p4d.24xlarge is 96 vCPUs, and ODCRs also count against the quota.
  • List several instance types and AZs. If your workload allows, list comparable types like g6e and g7 too. The more options, the easier it is to get capacity.
  • Run --dry-run first, and confirm permissions (create, describe, and cancel reservations, tagging, optional SNS).
  • Large quantities or long-term use, and also contact your AWS account team. The script can only grab capacity that occasionally frees up.

6 · Cost and release

  • ODCR billed at On-Demand rates as soon as it's active, even if no instances are running. Running instances aren't charged twice.
  • Savings Plans discounts also apply to ODCR.
  • Reservations created by the script have no end date,Can be canceled anytime:./grab-gpu.sh --release.
  • When running multiple jobs at once, use --tag separately, so releasing one doesn't affect the others.
