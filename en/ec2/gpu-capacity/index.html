Can't launch GPUs? First Capacity locked in

When GPUs are scarce, launching instances keeps failing with "insufficient capacity". This post uses a hotel-booking analogy to explain what On-Demand Capacity Reservations (ODCR) are, when to use the official Fleet, how to call the key APIs, and how to measure the results. Includes gpu-hunter, sample code for illustration.

1 · Choose an approach first 2 · What is ODCR 3 · How the sample chains the APIs together 4 · How to call the key APIs 5 · Pre-flight checks 6 · How to evaluate results 7 · GPU availability in Europe 8 · Costs and releasing Glossary
Disclaimer: The sample code in this post is meant to illustrate how to use the APIs. It is not a ready-to-run tool and must not be used in production.
Please understand these APIs, then write your own code for your needs. The sample is not an official AWS tool. Capacity reservations are billed at the On-Demand rate from the moment they're created, whether you use them or not. Refer to the official AWS documentation for limits, pricing, and quotas.
Start here: in three sentences
  1. You can't launch GPUs because that data center has no free machines right now.All you can do is: retry later, switch data centers (AZs), switch instance types, or ask for fewer instances.
  2. ODCR is like booking a hotel room in advance: once reserved, the capacity is held for you even if your instances are stopped; but billing starts the moment it's reserved, whether you use it or not.
  3. If you only need capacity in one AZ, start with AWS's built-in Capacity Reservation Fleet; to search across several AZs at once, you have to call the underlying APIs yourself. This post explains how to call these APIs, with gpu-hunter as a reference example.

4 · How to call the key APIs

The whole process uses only 4 APIs. Below is an example call for each, along with the most important things to watch out for:

① Which AZs offer this instance type? DescribeInstanceTypeOfferings

aws ec2 describe-instance-type-offerings --region eu-central-1   --location-type availability-zone   --filters Name=instance-type,Values=g6e.12xlarge   --query 'InstanceTypeOfferings[].Location' --output text

Skip AZs that don't offer this instance type; requests there will never succeed.

② Reserve capacity: CreateCapacityReservation

aws ec2 create-capacity-reservation --region eu-central-1   --instance-type g6e.12xlarge --instance-platform Linux/UNIX   --availability-zone eu-central-1a --instance-count 4   --instance-match-criteria targeted --end-date-type unlimited   --client-token "my-unique-id-0001"   --query 'CapacityReservation.[CapacityReservationId,State]' --output text
  • All or nothing: if there's no capacity, it returns InsufficientInstanceCapacity, you have to request fewer and try again (4 → 2 → 1).
  • Include the request ID(--client-token): If the network drops, resend with the same token and you won't end up with a duplicate reservation (see Figure 5).
  • Turn off the CLI's built-in retries(AWS_MAX_ATTEMPTS=1): In our tests with default settings, a single out-of-capacity error was silently retried into 3 attempts.
  • open or targeted: if your account already has instances of the same type running, use targeted; otherwise they will use up the reservation.

③ Check status: DescribeCapacityReservations

aws ec2 describe-capacity-reservations --region eu-central-1   --capacity-reservation-ids cr-0123456789abcdef0   --query 'CapacityReservations[0].State' --output text

pending This isn't a failure; it can take up to about 5 minutes to become active, don't cancel it.

④ Release: CancelCapacityReservation

aws ec2 cancel-capacity-reservation --region eu-central-1   --capacity-reservation-id cr-0123456789abcdef0

Canceling is free, and billing stops once you cancel; running instances keep running and are billed at the regular On-Demand rate.

Use the reserved capacity

  • open mode: instances with a matching instance type, platform, and AZ will Reservations are used automatically, just launch instances normally.
  • targeted mode: specify the reservation ID at launch:
aws ec2 run-instances ...   --capacity-reservation-specification 'CapacityReservationTarget={CapacityReservationId=cr-0123456789abcdef0}'

5 · Pre-flight checks

  • Is the quota sufficient?: check your On-Demand vCPU quota (Running On-Demand G and VT / P instances). Reservations also count toward the quota. For example, one p4d.24xlarge is 96 vCPUs.
  • Permissions: create, describe, and cancel reservations, and tag resources; SNS is also needed if you use notifications. First run --dry-run to confirm.
  • List several instance types and AZs: if your workload allows, list all instance types of the same class. The more options, the more likely you are to get capacity.
  • open mode "absorbs" running instances: if the account already has running instances of the same type in the same AZ, they will be absorbed into the reservation as soon as it becomes active, using up the capacity you secured. To avoid this, use --targeted.
  • Don't poll too often: creating reservations and all "modify resource" operations in the account share one rate limit quota(see Figure 6). Calling too fast can get the customer's own Auto Scaling and Terraform throttled.
  • run in the same region: in testing, describe requests took about 0.4 seconds in the same Region and about 1.3 seconds cross-Region (same-Region create requests were not measured separately).
  • Large volume or long-term use: contact your AWS account team at the same time. The script can only secure capacity that occasionally frees up.

6 · How to evaluate results

Whether you use the sample or your own code, we recommend Log every request(the sample writes a CSV file,tools/report.sh which you can summarize in a table). The key numbers to watch:

What to look at What it means
⭐ Time to fill Most important; reflects overall effectiveness
Time to first instance How soon you can start working
Success rate per instance type × AZ Where capacity is easier to get, so it goes first next time
Times throttled Should be 0; if not, increase the interval
Idle cost Reserved but unused: how much money was wasted (see CloudWatch utilization metrics)
Keep the comparison fair:Capacity keeps changing, so compare against a "baseline" approach. Two approaches Run in rotation, Don't run them at the same time in the same account, running each several times before looking at the results. For details, see How it works.

8 · Cost and release

  • Reservation Charged at the On-Demand rate once reserved, even if no instances are running; once instances are running, you pay only for the instances, with no double charge.Per-second billing, 60-second minimum.
  • Savings Plans discounts also apply to reservations.
  • Reservations created by the script have no end time,Cancel anytime, free of charge:./gpu-hunter.sh --release. Still pending can't be released yet; run it again in a few minutes.
  • Each failed attempt leaves an entry in your account failed Record: free, doesn't count against quota, and disappears after 60 minutes.
  • When running several jobs at once, use --tag separately, so releasing one doesn't affect the others.

Term In plain words
AZ(Availability Zone)A data center within a Region. Frankfurt has 3
ICEInsufficientInstanceCapacity: "This data center currently has no available capacity for this instance type"
ODCR On-Demand Capacity Reservation: "book" the instances first
open mode Reserved capacity "open to anyone": instances with a matching instance type and AZ use it automatically
targeted mode Reserved capacity "only for those who give the reservation ID": you must specify the reservation ID at launch
Quota The maximum number of vCPUs the account can use at once. If exceeded, you can't launch, regardless of availability
Throttling Too many API calls in one second, so AWS asks you to wait and try again
pending / active Reservation states: "Reserved, still being prepared" / "Ready"
Request ID(ClientToken)Give each request an ID; if the same ID is sent repeatedly, AWS processes it only once
Capacity Reservation Fleet AWS's official "keeps reserving for you automatically" feature; works in only one AZ
