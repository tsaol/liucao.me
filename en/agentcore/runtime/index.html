AgentCore Runtime:microVM or Instances

How to choose between the two compute options: comparison, cost calculator, hands-on tests.

1 · Comparison 2 · Cost 3 · Benchmarks 4 · Getting started
Conclusion
  1. Uses microVMs by default:Fast startup (seconds), pay per use, no ops.
  2. Need x86 / GPU, more than 8 hours, or root (to lock down networking or run containers)use Instances.
  3. With Instances, always delete sessions:Stopping a session doesn't shut down EC2, and these instances don't show up in the EC2 list by default.

Pitfalls we hit

  1. Stopping a session doesn't shut down the machine: you need to call DeleteCapacityProviderSession, otherwise you keep getting billed.
  2. Instances hidden by default: when querying, add --include-managed-resources.
  3. STANDARD mode permissions revoked: you can't switch users or change iptables; you need privileged mode.
  4. Requests are sent in chunks(chunked, no Content-Length).
  5. Privileged mode requires the latest SDK(boto3 ≥ 1.44.11).
  6. GPUs in Tokyo are x86 only: gr6 is AMD, not Graviton, and g5g isn't supported, so you need an x86 image.
  7. A single AZ often runs out of capacity: configure two subnets and allow several instance types; with multiple types allowed, you may get a fractional GPU (g6f).

4 · Getting started with Instances

# 1. Infrastructure role: trust bedrock-agentcore.amazonaws.com, attach BedrockAgentCoreRuntimeInstancesOperatorRolePolicy
# 2. capacity provider
aws bedrock-agentcore-control create-capacity-provider --name my_cp \
  --permissions-configuration capacityProviderOperatorRoleArn=<role ARN> \
  --compute-configuration '{"ec2Configuration": {
     "launchTemplateSource": {"launchParameters": {"operatingSystem": "LINUX_ARM64",
        "instanceRequirements": {"allowedInstanceTypes": ["m8g.large"]}}},
     "vpcConfiguration": {"subnets": ["<subnet>"], "securityGroups": ["<security group>"]}}}'
# 3. Attach the runtime to the capacity provider
aws bedrock-agentcore-control create-agent-runtime --agent-runtime-name my_agent \
  --agent-runtime-artifact containerConfiguration={containerUri=<ECR image>} --role-arn <execution role ARN> \
  --capacity-provider-configuration capacityProviderArn=<capacity provider ARN>
# 4. When done: stop, then delete the session
aws bedrock-agentcore stop-runtime-session --agent-runtime-arn <runtime ARN> --runtime-session-id <session ID>
aws bedrock-agentcore delete-capacity-provider-session --capacity-provider-id <ID> --session-id <session ID>
