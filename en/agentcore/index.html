Amazon Bedrock AgentCore:A full suite of services for running agents

Putting an agent into production takes more than calling a model: where it runs, how it's isolated, how it calls tools, what it remembers, whose identity it uses, and how well it performs. AgentCore splits these into separate managed services. This page is the overview; Runtime has its own in-depth page.

Accessed 2026-11-25.AWS official documentation is authoritative for the service list, limits and pricing; the "measured" results in this article are my own tests in the Tokyo Region (ap-northeast-1).
Start here: in three sentences
  1. AgentCore is a complete suite of managed services on AWS for "running agents".You choose the framework (Strands, LangGraph, CrewAI...) and the model (in Bedrock or elsewhere),Each service can be used on its own.
  2. At the core is Runtime:Put your agent in a container,An isolated environment for each session, pay per use, scales to 0 when idle.
  3. Other services are built around it:Tools (Gateway, Code Interpreter, Browser), memory and identity (Memory, Identity), governance (Policy, Registry), quality (Observability, Evaluations, Optimization).

1 · What it is

Key points Key points of this section
  • Official definition: using any framework and any foundation model,Securely, at scale Build, deploy and run agents,No infrastructure to manage.Docs · What is
  • The services are modular:Use them together, or use just one, for example using only Runtime to run your own agent, or only Gateway to turn APIs into MCP tools.Docs · What is

Actually putting an agent into production takes more than "calling a model". You need a lot of other things: where it runs, how it's isolated, how it calls tools, what it remembers, whose identity it uses to access other systems, how to see what it did, and how well it did. AgentCore breaks these into separate managed services, You write only the agent logic itself.

Three typical use cases from the official docs:Agent applications(customer service, process automation, data analysis, coding assistants),Tools and MCP servers(wrap existing APIs and Lambda functions as tools),Agent platform(a "paved road" for internal developers).Docs · What is

2 · 13 services in one diagram

Key points Key points of this section
  • Grouped into five categories by purpose:Runtime, tools, memory and identity, governance, quality.Docs · What is
  • For a first try, the fastest entry point is Harness:Define and run an agent with a single API call(model, prompt and tools specified directly in the request).Docs · What is

Run

Runtime A managed agent runtime with per-session isolation; two compute options: microVM and Instances (see next page).
Harness A managed agent loop: it handles orchestration, tool calls, and memory; each session gets its own microVM with a file system and shell.

Tools

Gateway Turns APIs, Lambda functions, and existing services into MCP tools, and can also connect to existing MCP servers.
Code Interpreter An isolated sandbox where agents run Python / JavaScript / TypeScript.
Browser A managed cloud browser that lets agents fill in forms, click through web pages, and scrape information.
Web Search / Web Answer Managed tools added in 2026-11 (not part of the official 13 services): search the web in a single call, or get a cited answer directly.

Memory and identity

Memory Short-term memory (multi-turn conversations) and long-term memory (across sessions), shareable across multiple agents.
Identity Agent identity and authorization, integrating with existing identity systems such as Cognito, Okta, and Entra ID.

Governance

Policy Deterministic rules: every tool call is intercepted and checked before it runs. Rules can be written in natural language or a Cedar-compatible policy language.
Registry An internal catalog of agents, MCP servers, tools, and skills, with review and publishing workflows.
Payments Lets agents make small payments to call paid APIs (x402, MPP protocols), with configurable spending limits.

Quality

Observability Traces, logs and metrics (OpenTelemetry) for every step, viewable in CloudWatch.
Evaluations Automatically evaluates how well agents complete tasks, using built-in or custom evaluators.
Optimization Generates improvement suggestions (prompts, tool descriptions) from traces, then validates them with A/B tests.

3 · Where to start

Key points Key points of this section
  • Just want to try an agent quickly:Using Harness, no container required.Docs · What is
  • You already have your own agent code (any framework):Package it as a container and put it in Runtime, you just need to implement two interfaces:GET /ping and POST /invocations, port 8080.Docs · Getting started with Instances
  • Harness: the model, system prompt, and tools are all defined in a single call; good for prototypes and small internal tools.
  • Runtime: your own framework and dependencies, your own container image; good for production and cases where you need control over the environment.
  • Add other services as needed: add Gateway to call company APIs; add Memory to remember users; add Policy to control what the agent can do; after launch, use Observability and Evaluations to monitor quality.

4 · Recent updates (second half of 2026)

Key points Key points of this section
  • The new-generation Runtime is the default starting 11-12(including Tokyo): sessions start from snapshots; a 2 GB image starts in under 2 seconds at P75.What’s New 11-12
  • Runtime instances(GA on 8-06) lets agents run on EC2 in your own account; privileged mode, nested virtualization and G7 GPUs were added later.What’s New
08-06 Runtime instances are generally available: run agents on EC2 in your own account, with sessions up to 14 days.
09-18 Next-generation Runtime (V2) released: memory is allocated on demand and reclaimed after use, and cold starts hold steady at about 2 seconds.
11-05 Web Answer: a managed tool that returns synthesized answers with sources.
11-10 Web Search API: search the web in a single call.
11-12 V2 becomes the default version for new runtimes; sessions up to 8 vCPU / 32 GB, images up to 10 GB.
11-16 Runtime instances are now available in 6 more Regions.
11-18 Runtime instances support privileged mode: agents can install system software and run nested containers.
11-19 Runtime instances support nested virtualization (KVM, Intel instance types); Harness adds Strands default configuration, built-in tools, and lifecycle hooks.
11-20 Runtime instances support G7 GPU instances.
