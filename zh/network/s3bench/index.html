S3 下载加速基准测试

测试从欧洲 S3 存储桶下载 2 GiB 文件的速度 | 2026 年 6 月

测试环境

文件大小： 2 GiB （随机数据）

源端（客户端）： AWS 中的 EC2 实例

存储桶 1： eu-south-2 （西班牙，萨拉戈萨）

存储桶 2： eu-central-1 （德国法兰克福）

存储桶 3： eu-north-1 （瑞典斯德哥尔摩）

访问方式： 私有（无公开访问）

区域地图

测试方法

1. 基线（aws s3 cp） — 使用 AWS CLI 进行标准单流下载。内部使用默认分段设置，但通过单个 TCP 连接从 S3 下载。 
aws s3 cp s3://<your-bucket>/file.bin ./output.bin --region eu-south-2
2. S3 Transfer Acceleration — 通过 CloudFront 边缘站点路由数据。客户端距离 S3 存储桶所在区域较远时，可从最近的边缘站点接入 AWS 骨干网，加快传输。 
aws s3api put-bucket-accelerate-configuration --bucket bucket --accelerate-configuration Status=Enabled
aws s3 cp s3://<your-bucket>/file.bin ./output.bin --endpoint-url https://s3-accelerate.amazonaws.com
3. 并行 Range GET（16 个分块） — 将文件拆分为 16 个字节范围分段，并通过后台进程并发下载。每个分块使用单独的 TCP 连接访问 S3，从而占满可用带宽。 
for i in $(seq 0 15); do
  aws s3api get-object --bucket bucket --key file.bin \
    --range "bytes=${start}-${end}" chunk-${i}.bin &
done
wait
4. 调优分段传输（64MB 分块） — 使用 aws s3 cp 并调整分段分块大小配置，测试更大的传输单元能否比默认设置提升吞吐量。 
aws s3 cp s3://<your-bucket>/file.bin ./output.bin --region eu-south-2 \
  --cli-read-timeout 300 --expected-size 2147483648

主要发现

并行 Range GET 快 13 倍 — 将文件拆分为 16 个并发字节范围请求，可占满网络带宽，在 2 秒内下载 2 GiB（约 9.5 Gbps）。
Transfer Acceleration 在 AWS 内部没有帮助 — S3 Transfer Acceleration 面向 AWS 外部的客户端。如果源和目标都在 AWS 内，它只会因经过 CloudFront 边缘跳转而增加延迟，没有任何好处。
在欧盟内部，区域选择几乎无影响 — 得益于 AWS 骨干网，同一客户端从西班牙和法兰克福获得的吞吐量几乎相同。
调整分段大小没有效果 — AWS CLI 内部已使用最优分段设置。调整分块大小并不能提升单流吞吐量。

推荐

在 AWS 内部从 S3 获得最快下载速度：

使用并行字节范围 GET 请求（16-32 个并发流）

该方法适用于私有存储桶，无需特殊配置，并能随可用带宽线性扩展。
